## Finding

1. `codes/360-12-24.json` (twisted-torus code of Liang, Liu, Song, Chen, arXiv:2503.03827) is,
   up to an explicit qubit permutation, the bivariate bicycle code of Bravyi et al. (Nature 627,
   778 (2024), arXiv:2308.07915) with (l,m) = (30,6), A = x^9 + y + y^2, B = y^3 + x^25 + x^26,
   listed there as [[360,12,<=24]]. Liang et al. already relate their twisted-torus code to
   Bravyi et al.'s construction; this note adds an explicit permutation and a row-space check
   for the board's indexed instance.
2. Two separately written exhaustive searches find no X-logical of weight <= 22. If those
   searches are complete and correct, then parity, an explicit weight-24 logical and BB duality
   give d = 24. This is computational evidence outside the board's certification tiers. The
   PR requests no change to the entry's distance, confidence or certification status.

## Equivalence

Board file conventions (from its provenance): L = <(0,30),(6,6)>, f = 1 + x + x^-1 y^3,
g = 1 + y + x^3 y^-1 on Z^2/L, H_X = [f|g], H_Z = [g-bar|f-bar] (bar: x, y -> x^-1, y^-1).
Bravyi convention: H_X = [A|B], H_Z = [B^T|A^T], monomial x^a y^b puts a 1 in row h, column
h+(a,b); left (i,j) -> 6i+j, right -> 180+6i+j.

phi: Z^2/L -> Z_30 x Z_6, x -> u = (4,3), y -> v = (21,1) kills (0,30) and (6,6). It is onto,
because u - 3v = (1,0) and 4v - 21u = (0,1). Both groups have order 180, so phi is an
isomorphism. On supports (mod (30,6)): supp phi(f) = {0, u, 3v-u} = supp B - (26,0) and
supp phi(g) = {0, v, 3u-v} = supp A - (9,0).
Board left qubit h goes to Bravyi right qubit phi(h)+(26,0), and board right qubit h goes to
Bravyi left qubit phi(h)+(9,0). Under this map, board X-check h goes to Bravyi X-check phi(h)
and board Z-check h to Bravyi Z-check phi(h)+(5,0); this was checked for all 180 rows of each.
The board-index-to-site map can be read off p: board qubit c < 180 sits at h with
phi(h) = site(p[c] - 180) - (26,0).

## Evidence for d = 24

Package: Zenodo, DOI 10.5281/zenodo.23342751 (code, logs, explicit logicals, method write-up).

1. Upper bound: weight-24 X-logical in Bravyi indexing
   0,12,33,39,60,74,94,100,122,144,159,165,171,174,223,224,242,255,270,294,299,304,352,356
   (H_Z v = 0, rank [H_X; v] = 175 > 174). Under p^-1 it is the board-indexed X-logical
   14,25,33,39,57,100,110,123,132,136,204,211,219,228,231,238,252,255,266,290,291,292,312,317.
2. Weights <= 22 (exact GF(2) arithmetic). Translations are code automorphisms, transitive on
   each block, so some minimum X-logical T contains left site 0 (anchor L), or has no left qubit
   and contains right site 0 (anchor R). T has no nonempty proper zero-syndrome subset (else it
   and its complement have zero syndrome and one is a lighter logical), as in the anchored
   cluster search of Rowshan and Devitt (arXiv:2609.39395). At a zero-syndrome node the support
   is tested for lying outside rowspace H_X, then the branch stops. Otherwise, pick an
   unsatisfied check c, whose candidates are its qubits not yet chosen or excluded. Child i adds
   candidate q_i and excludes q_1..q_{i-1}, and exactly one child stays consistent with T. If
   the pruning bounds are valid, a completed run with both anchors therefore excludes
   d_X <= 22. The bounds on remaining weight are degree, disjoint-check packing, cover and
   parity; the package README (Sec. 3) justifies each. Nodes, anchor L + anchor R:
   - program 1: 1,168,434,648 + 3,195 nodes, 4,743 s, none found
   - program 2 (written without reading program 1's code; mirrored convention, different
     prunes and data structures): 2,896,608,451 + 2,120 nodes, 7,896 s, none found
   Hardware: one core of a laptop i7-1185G7. Both programs follow the same anchored-search
   argument, so they are not independent in their mathematics.
3. Weight 23: every column of H_Z has weight 3, so 1^T H_Z = 1^T over GF(2). Hence H_Z v = 0
   implies |v| is even.
4. d_Z = d_X by Lemma 1 of Bravyi et al.

Controls: both programs give d = 12 for the gross code [[144,12,12]]. Program 2 reproduces
[[72,12,6]], and on a deliberately altered gross code (d = 10) it agrees with a SAT encoding.

Prior bounds: d >= 16 (Kirtchakov, https://github.com/05oz/certify at commit b3d00ba, replayed
as d_X >= 16 plus duality) and d <= 24 (Bravyi et al.; also this entry's witnesses).

## Limits

The package has no independently checkable proof certificate for d >= 24, and no certificate
of a kind the board accepts. The weight-24 upper bound is independently checkable. Our SAT
attempt at n = 360 did not finish at w <= 13 within 10 minutes. The board's currently
supported certification envelope (d <= 13, k <= 12) does not cover this case. A bug shared by
both programs cannot be fully ruled out. The search code and this text were written with Claude
(via Claude Code) under the author's direction. Reviews of the release were by AI systems
(Claude, OpenAI Codex) only, with no human expert review. Rerun with verify.py from the
Zenodo archive: `python verify.py` (quick, about 1-2 min) checks the logicals and the parity and
duality steps, but not the weight-22 search. `python verify.py --full`
reruns that search with program 1 (about 79 min), and `--full-engine2` uses program 2 (about 2.2 h).

## Implication for searches

Compute was deliberately low: consumer AI subscriptions and one laptop core (the longest
search took 7,896 s). An anchored exhaustive search with the even-weight bound reached weight
22 at n = 360, k = 12. Producing a separately checkable proof artifact for such searches remains
future work.
