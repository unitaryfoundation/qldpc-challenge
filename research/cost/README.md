# What a rung costs: the wall-time table

`measure.py` records, for a fixed grid of board entries that covers the cap
corners (`BASE_MAX_N` 700, `MAX_N` 1000, check weight 8 and 12/16/24/32,
distance near the extended cap of 40) and both code types, what the steps of confirming a candidate cost
on one machine (issue #4026). `cost_table.json` is the record and
`cost_table.md` the table; measurements are generated by the script. A distance-revision follow-up may
update a row's current slug while preserving the original measurement identity.

Measured, per entry:

| column | what ran |
|---|---|
| gate | `verify/validate_candidate.py` end to end, with the board already loaded once (the cold board pass is reported separately) |
| of which refute | the gate's own refutation, `heuristic_distance.refute_check`: n-scaled RIS trials under a 10 s wall cap checked between trials, so it runs 8 to 12 s at small n and overruns by its last trial at large n (42 s at n = 696, k = 352) |
| RIS 20,000/side | the pure-Python RIS search at the `qldpc submit` default, per side (one Pauli-weight side for a stabilizer code). Up to n = 300 it is measured at 20,000 trials; above, where a trial costs seconds, it runs at 2,000 trials and the table shows the implied 20,000-trial time (marked ~) from the measured per-trial rate, with the measured count and time beside it |
| fast 200,000 and fast 2,000,000 | the C++ accelerator (`make fast`), 8 threads, at a screen-sized budget and at the submit default |
| submit search | the witness search `qldpc submit` performs before packaging: the RIS passes plus the 2,000,000-trial accelerator pass, summed from the columns to its left |
| certify X, certify Z | `verify/certify.py`'s question per side: one MILP per logical generator with a 60 s limit each, the whole side under a 120 s wall cap. A side reads exact, refuted, MILP limit (every generator was tried, at least one hit its limit, so the distance stays an upper bound), or wall cap (killed; `generators` says how many MILPs the side needs). Stabilizer codes have no certifier yet and read n/a |

What is not measured: the kit's screens (`research/kit/search.py`, 400 trials
per candidate, seconds for hundreds of candidates) and `qldpc submit`'s
packaging after the search, which are not where the time goes.

## Reading it

- A time is what this machine took on that day, with the environment block
  saying which machine. CI runners are not this machine; the shape of the
  curve carries over, the constants do not. Nothing here is a guarantee or a
  gate input, and `verify/` is only called, never changed.
- The gate is bounded by construction: the structural pass is seconds, the
  refutation is capped at 10 s, and the dedup is one warm board lookup. The
  structural time in the table is the warm one (the entry had been verified in
  the board pass); a fresh candidate pays the structural pass itself, about the
  cold board pass divided by the board size. What grows with shape is the RIS
  search in Python and the certifier.
- Exact certification is where the ladder ends. Every side at the cap corners
  hits a limit; the budget line for a sweep therefore counts certification as
  a separate post-hoc tier for standouts, as
  fieldnotes/2026-07-01-confirmation-is-the-bottleneck.md already said.

## Re-measuring

```
uv run --frozen --with pybind11 --with setuptools python verify/setup_gf2_fast.py build_ext --build-lib verify --build-temp build/gf2_fast   # or: make fast
uv run --extra certify python research/cost/measure.py run           # the grid, a few hours
uv run --extra certify python research/cost/measure.py run --only 96-16-6 --resume
uv run python research/cost/measure.py render                        # the .md from the .json
```

The `certify` extra brings scipy for the MILP. `--resume` keeps the entries
already in the table, so an interrupted run continues; `--only` re-measures
named entries. The grid is the `GRID` list in `measure.py`; a slug that leaves
the board is reported and skipped, and each record carries the blob hash of the
entry it measured. `test_measure.py` checks that every grid entry is on the
board and that the committed table covers the grid with a status on every
certification side.

When a measured entry is renamed after a distance correction, `slug` follows
the current board and `measured_slug` retains the original name. Its `blob`,
`d`, role, timings, and certification outcomes still describe the original
input at the recorded measurement date; they are not measurements of the
revised distance claim. The rendered table labels those rows. A fresh run
without `--resume` measures the revised inputs; `--resume` retains the stored
historical records.
