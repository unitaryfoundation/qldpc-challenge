[[849,9,11]] — multi-band dense-packed surface code, 2 bands x 5 patches

Direction & hypothesis

Target cell: local-2d-single x weight-4, the d = 11 column. The board's best entry in that column is [[667,7,11]] (codes/667-7-11.json, kd^2/n = 1.270), from the same multi-band packing family at rows = 2. That entry sits at the top of the n <= 700 range the family was first mapped under (fieldnotes/2026-09-01-multiband-dense-packing-method.md). The hypothesis was that the two-band ladder continues past that range with kd^2/n still rising, because each added patch adds logicals at a fixed per-patch qubit cost. It does: this code reaches kd^2/n = 1.283 at n = 849, and no CSS entry on the board has n <= 849, k >= 9, d >= 11 and w <= 4.

What was searched

The builder is research/multiband_surface.py, which states the packing mask as a rule over (d, rows, m, pitch) and is checked bit-exactly against research/build_dense_surface.py at that builder's own configuration (rows = 2, m = 3, pitch = d - 1). This code is the same rows = 2, pitch = d - 1 regime at m = 5. The sweep that produced it covered rows 2-12 and m 2-40 at the two measured pitch regimes, keeping 700 < n <= 1000 points that are CSS, single-Tanner-component, w <= 4 and Pareto-undominated in their cell; k was recomputed by exact GF(2) rank at every point, never from the closed form. 32 configurations survived the trusted gate; this is one of them.

Evidence trail

Confirmation ladder for the submitted code, each rung a fresh seed unless marked otherwise, reading the lightest logical found:

| budget (trials/side) | lightest logical | | ---: | ---: | | 8,000 (trusted gate verify/validate_candidate.py, nominal budget under a 10 s wall cap) | 11 | | 1,000,000 (seed 101) | 11 | | 1,000,000 (seed 102) | 11 | | 1,000,000 (seed 103) | 11 |

4 fresh-seed rung(s) agree at the best bound, the deepest of them at 1,000,000 trials per side. The submitted witness reproduces it: X: d <= 11 (upper_bound), Z: d <= 11 (upper_bound).

The three 1M rungs are research/audits/leader_audit.py ladder with --pair-depth 64 on the C++ backend (verify/gf2_fast.cpp), both sides searched every rung, the depth fieldnotes/2026-07-01-trial-depth-floors.md asks for at n >= 300. They are three seeds at one depth, not a rising ladder. The distance is also certified exact: verify/sat_certify.py (CryptoMiniSat, selector encoding, pairing set spanning all 9 logical classes) returns UNSAT at weight 10 on both sides (X 12.1 s, Z 22.2 s), recorded in certs/849-9-11.json at verification level solver: a solver verdict, not a proof-checked or formal one. The code JSON keeps upper_bound, as most certified entries do; the board reads the exact tier from the certificate. Every check matrix has column weight at most 2, so each side's distance is also a shortest odd cycle in a graph; an independent computation of that agrees (d_X = d_Z = 11).

Dead ends

  • Four of the 32 surviving configurations have since been dominated by entries

    • merged after the sweep, so a staged point is re-checked against the live board before it is packaged, not at sweep time.

  • The closed form k = rows*m - rows//2 disagrees with exact GF(2) rank outside

    • the two pitch regimes, so it is not usable as a screen.

  • Packing bands tighter than pitch d - 1 at rows = 2 collapses the distance

    • while n and k still look right.

Tools

Model: Claude Opus 5.5 (Claude Code). Repo tooling: research/multiband_surface.py, research/kit/submit.py, research/audits/leader_audit.py, verify/gf2_fast.cpp, verify/sat_certify.py. The local verdict is verify/validate_candidate.py; the bundle was assembled by research/kit/promote.py. Compute: about 7 min for the 3M-trial ladder and about 34 s for the SAT certificate, on 16 threads.
