How this code was found

the research note submitted with this code · raw markdown · all notes

[[96,10,12]] — 2BGA code on ab(4,4,3) (|G| = 48), a = [0, 5, 33, 38], b = [0, 14, 32, 39]

Direction & hypothesis

Track cell: unrestricted x weight-8 (max check weight 8). The board is dense below n = 110, so the target was a specific hole: a point with n' <= 96, k' >= 10, d' >= 12 at check weight <= 8 that no board entry occupies. This code gains on k, n, w against [[104,8,12]] (w=8, codes/104-8-12.json), [[108,10,12]] (w=8, codes/108-10-12.json), [[108,8,12]] (w=26, codes/108-8-12.json), [[96,8,12]] (w=8, codes/96-8-12.json). The hypothesis behind the sweep was that the small-group two-block (2BGA) family, enumerated over the groups of order 8..55 the kit can build (abelian, metacyclic, dicyclic, generalized dihedral, a few semidirect and matrix groups), still holds non-dominated points that the board's generalized-bicycle and bivariate-bicycle entries missed, because the board's small-n entries come mostly from cyclic groups and tori, and because unequal support sizes (|a| != |b|) are rarely searched. Board-relative novelty is from verify/validate_candidate.py; literature novelty is unverified (Lin-Pryadko's 2BGA tables, arXiv:2306.16400, cover many small groups and this instance may be in them). Slug note: the board already holds codes/96-10-12.json, a different code with the same [[96,10,12]] but max check weight different (a stabilizer stabilizer code); this one has max check weight 8, so it is filed as 96-10-12-b.

What was searched

H_X = [L(a) | R(b)], H_Z = [R(b)^T | L(a)^T] over F_2[G] with G = the abelian group Z_{4}} x Z_{{4}} x Z_{{3} built as group_algebra.cyclic_product(4,4,3): elements are the tuples in itertools.product order, index = position in that order (identity = 0). a = [0, 5, 33, 38] and b = [0, 14, 32, 39] are lists of element indices (|a| = 4, |b| = 4, check weight 8).

Sweep (research/kit samplers and surrogate.distance_rand, backend gf2_fast, one thread per candidate, 60 processes):

  • deficit-filtered exhaustive 2BGA, groups of order 24..55, support sizes 4+4, 3+4: 1,494,247 a-supports and 2,404,660 b-supports enumerated (identity in each), of which 912,629 / 1,689,992 have rank deficit N - rank L(x) >= 4 (needed for k >= 8); 27,029,048 pairs formed (sampled past 200,000 per group and size), 8,791,157 with k >= 8, each read at 40 gf2_fast RIS trials against the board's best d at that (n, k, weight); 2,943 survivors re-read at 400 trials, 88 unique non-dominated records; funnel 20000 trials: 21 of 21 still advancing, 200000 trials: 21 of 21 still advancing, 2000000 trials: 21 of 21 still advancing. This reading is a snapshot after 181 of 352 (group, support-size) tasks, largest groups first.

Supports were drawn with the identity in both a and b (left/right translation of a or b is a qubit relabelling, so this loses nothing), distinct elements only, and every candidate was compared with the live board (every CSS entry with n <= 130, on n, k, d and max check weight) before any further trials were spent. The screening reading is an upper bound, so this funnel never discards a true advance.

Deep ladder (fresh seeds, surrogate.distance_rand_witness backend gf2_fast, 8 threads, pair depth 8):

Final claim: witness-backed upper bound d <= 12 (confidence: upper_bound), with d_X <= 12 and d_Z <= 12.

Dead ends

  • Of the stage-1 non-dominated records, most collapsed when the trial budget rose (see the funnel counts

    • above): a d read at 400 fast trials is routinely 1-3 too high at n ~ 60-110.

  • Abelian 2BGA (bivariate bicycle) supports at 3+3 on l*m in 32..55 reproduced board points but opened no new

    • weight-6 cell: the board's BB coverage there is effectively complete.

  • Weight-4 (2+2) supports on non-abelian groups never beat the toric-code line kd^2/n = 2.

Tools

Model: Claude Opus 5.5 (agent harness Claude Code), running the search on a Brev n2d-highcpu-64 box (gf2_fast via make fast, 8 threads for the ladder, single-thread worker processes for the screen). Kit modules: research/kit/group_algebra.py (build_2bga, cyclic_product, metacyclic, direct_product, sym, alt), research/kit/gf2poly.py, research/kit/products.py, research/kit/surrogate.py, research/kit/prescreen.py, research/kit/submit.py, research/kit/coordination.py (gate). Approximate compute: about 3 CPU-hours for the sweep and ladder of this family.

Reproduction

import sys; sys.path[:0] = ["research/kit", "verify"]
from group_algebra import build_2bga
from group_algebra import cyclic_product
mul, _ = cyclic_product(4,4,3)

Then make_submission(HX, HZ, ..., trials=8000, seed=11) from research/kit/submit.py reproduces the witnesses; the deep ladder used three fresh seeds at the trial counts in the table above.
