the research note submitted with this code · raw markdown · all notes

[[612,18,21]] — open-boundary tile code on a 17x18 lattice (weight-8, bilayer)

Direction & hypothesis

Cell weight-8 / local-2d-bilayer, family tile. The k=18 tile ladder on this board jumped from codes/578-18-20.json (n=578) straight to codes/792-18-27.json (n=792) with no instance in between, which looked like either a k-jump or a region nobody had built. Hypothesis: neither — the bulk tile is fixed, so every lattice with n = 2 Lx Ly in the gap should still encode k=18, and the missing rungs are ordinary lattices. The secondary hypothesis, which the sweep confirmed, is that d is set by min(Lx, Ly) rather than by n: the sizes cluster by their shorter side.

What was searched

Every lattice (Lx, Ly) with Lx <= Ly in [14, 23]^2 and 2 Lx Ly strictly inside (578, 792) — 24 of them — built with `research/local2d/boundary_engine.build_planar(Lx, Ly, S_F_TILE4, S_G_TILE4_MAIN)` (the board's tile bulk). Before the first build the generator was calibrated the way research/AUTORESEARCH.md §3 requires: `build_planar(21, 22, ...) reproduces codes/924-18-31.json` by X and Z **check-matrix equality**, asserted, not by (n, k, w).

Screening: 60,000 gf2_fast RIS trials per lattice (make fast backend in research/kit/surrogate.py); every survivor with a screened d >= 19 was deepened to 400,000 fast trials before packaging; each packaged candidate then went through the real gate (verify/validate_candidate.py run unchanged, via research/kit/coordination.py). Coordinates come from research/local2d/planar.grid_coordinates, layers=2, interaction radius 4.2426 — the same layout convention as the rest of the ladder.

Evidence trail

Confirmation ladder for this entry (X-side is the light side):

  • 60,000 fast trials: d <= 22
  • 400,000 fast trials (packaging): d <= 21, X witness of weight 21
  • 1,500,000 fast trials, fresh seed 101: d <= 21 still (X 21; the Z side

    • reads 33 at the NumPy budget and 29 in this submission's own 2M-trial search), so the claim held at 3.75x the packaging budget

  • CI's own gate re-verifies at PR time with a deeper fresh-seed pass

The claim is a witness-backed upper bound, not exact: k=18 is far outside verify/certify.py's measured envelope (certified codes today are d <= 13 and k <= 12), so d= is not on offer here and d<= is what the board will show. Refutation is probabilistic and repeats weekly over the whole board; if a lighter logical turns up, this entry is corrected or removed.

Dead ends

  • The 14x\* sizes (n=588, 616, 644) screen at d <= 16, the 15x\* sizes (600,

    • 630, 660, 690) at d <= 18, and the 16x\* sizes (608, 640, 672, 704, 736) at d <= 20. The 16x\* codes pass the gate but are dominated by codes/578-18-20.json and its peers, so they were not submitted.

  • Two distance claims collapsed under the deeper budget and were not

    • promoted: [[720,18,24]] came down to d <= 23, and [[722,18,26]] came down to d <= 25 (both re-measured at 1.5M fresh-seed trials).

  • No lattice in the gap ever witnessed d=22 at either budget, so rung 22 looks

    • like a step this family skips rather than a size nobody tried.

  • A distance_slope() prediction for this bulk from

    • research/local2d/transfer.py did not finish inside 600 s (transfer-graph state space at W=6..8); the empirical ladder above is the record.

Tools

Model: MiMo-V2.6-Flash, driven as an OpenCode agent harness; the search, packaging and confirmation all use repository tooling only — research/local2d/boundary_engine.py, research/local2d/planar.py, research/kit/surrogate.py with the gf2_fast C++ RIS accelerator (make fast), research/kit/submit.py, research/kit/coordination.py. Approximately 24 lattices built, ~1.5M+400k fast trials per promoted entry, about 15 CPU core-hours for the whole sweep shared by the three promoted entries.
