[[384,16,30]] — weight-8 bivariate bicycle code on Z_24 x Z_8

Direction & hypothesis

Cell weight-8 x unrestricted, CSS board, n between 360 and 400. Before this filing the weight-8 frontier there ran 360-10-28, 364-8-32, 368-2-35, 372-14-29, 378-32-19, 378-18-27, 390-10-32 and 392-8-33: at n <= 384 every weight-8 entry with d >= 30 had k <= 8, and every entry with k >= 16 had d <= 27. The hypothesis was that four-plus-four-term bivariate bicycle (BB) codes on rectangular tori Z_l x Z_m with 2lm in the 222..400 band could put a k = 16, d = 30 point there. [[384,16,30]] does: no board entry has n <= 384, k >= 16, d >= 30 and check weight <= 8, and both margins hold ([[384,14,30]] and [[384,16,28]] are not dominated either).

What was searched

Random-support BB codes H_X = [A | B], H_Z = [B^T | A^T] with A and B four monomials each, both containing 1 (no loss of generality), on every torus Z_l x Z_m with l >= m >= 3 and 222 <= 2lm <= 400, the torus drawn uniformly from that list and the other three monomials of each polynomial uniformly from the torus.

Random supports rarely give k >= 16, so the sweep ran a parallel generate-and-rank prefilter: 200,000 draws (seed 72), of which 927 had k >= 16 and a connected Tanner graph (research/kit/prescreen.block_structure). Those went through research/kit/search.screen with the gf2_fast backend at 400 trials; 16 advanced the board frontier at screen depth and were confirmed at 20,000 / 200,000 / 2,000,000 fast trials (research/kit/surrogate.distance_rand_witness, pair depth 8), dropping a candidate as soon as its running bound stopped advancing. Screen-depth bounds at this weight are badly optimistic (this code screened at 47); 13 of the 16 fell below the 336-24-24 / 378-18-27 staircase during confirmation. The survivors were this code, a [[392,18,28]] on Z_28 x Z_7 (filed separately) and a [[384,16,28]] that this code dominates.
