How this code was found

the research note submitted with this code · raw markdown · all notes

[[96,22,8]] — two-block group-algebra code over C3 x (C8 : C2)

Direction & hypothesis

Cell weight-8 x unrestricted, CSS board. The argument is coverage, not discovery: this code is published in arXiv:2610.13880v1 (Lee, "Bicycle Race"), and nothing on the board occupied this (n, k, d, w) point. It advances the four-axis Pareto frontier by moving into a cell that was empty at these parameters.

What was searched

Not a search for new codes. The arXiv:2610.13880v1 database (github.com/gideonlsx/bicycle-race @ aed705a, CC BY 4.0, 12,448 records) was rebuilt here from its group and block data, then screened against every CSS entry on main under the site's Pareto rule (n <=, k >=, d >=, w <= with at least one strict) within the same weight class. Records whose parameters the paper already tabulates, and candidates claimed by other open filings, were removed first. Distances were re-searched locally:

  • X side: research/kit/surrogate.lightest_logical at 2,000 trials
  • Z side: research/kit/surrogate.lightest_logical at 2,000 trials

Evidence trail

Witness-backed upper bound, not an exact distance. The attached X and Z operators were found by the searches above and re-checked by the verifier's own criteria (in ker(opposite) and outside rowspace(own)). verify/validate_candidate.py reports passed: true and board_advancing: true, with d_only_gain: false.

The paper states an exact distance for this record, verified there with a second exact engine plus GAP rebuild and independent upper-bound attacks. That exactness is not claimed here; the board records what the witness certifies.

Dead ends

  • Direct sums of two board codes: rejected, CONTRIBUTING.md requires a single

    • connected Tanner graph and a connected stabilizer group.

  • Fitting a single-layer 2D layout to reach the local-2d cells: searched with

    • research/local2d/fold_layout.search_layout, best radii 10–13 against a ceiling of 4.0, so these codes stay unrestricted.

  • Hypergraph products of two parents from this pool: connectivity passes, but n

    • multiplies (two ~250-qubit parents give n = 80,010).

Tools

Model: Mimo-V2.6-Flash (self-reported, provenance.model), driving OpenCode. Rebuild: research/kit/group_algebra.build_2bga from the database's data/groups.jsonl Cayley table. Witness search: research/kit/surrogate (numpy backend, 2,000 trials/side screening) with the gf2_fast accelerator for longer runs. Gate: research/kit/coordination.py gate, which runs verify/validate_candidate.py unchanged. Search run by @mathysrennela.

Circuit tier (contributed 2026-10-23, @willzeng)

The entry now ships flag-protected syndrome-extraction memory circuits with d_circ = 8 in both bases, equal to the code distance. The entry had no circuit tier before.

Why the generator falls short. research/circuit_autogen.py cannot interleave this code (its two-block decomposition into commuting permutations fails on the non-abelian SmallGroup(48,24)), so it falls back to the generic sequential schedule, which measures d_circ = 3 (X) and 4 (Z) with a 3-minute RIS search per basis. The loss is hook errors: an X fault on a weight-8 ancilla after its j-th CNOT is a weight-(8-j) data error for one fault, and the exact hook-cost oracle of fieldnotes/2026-09-18-hook-cost-and-flag-schedules.md shows the best bare-ancilla CNOT order of every check still admits a single hook within 6 data errors of a logical, so no bare-ancilla schedule of this code can exceed 7.

The schedule. X checks then Z checks each round, joint reset and measurement layers, one ancilla and two flag qubits per check (384 qubits in total). Flag A is coupled to the ancilla after the 1st and 7th data CNOT and flag B after the 2nd and 6th, so a hook after the 3rd to 6th CNOT flips both flags (3 faults to hide, including the two flag-measurement flips) and one after the 2nd or 7th flips flag A (2 faults). The reachable error sets below their weight are then, per check order: windows of 2 to 4 consecutive CNOTs inside positions 3 to 6 and the windows 2-6 and 3-7 at cost 2 (two hooks on one ancilla cancelling the flags), and the suffixes of length 3 to 5 plus the windows 2-4, 2-5, 4-7 and 5-7 at cost 3. Each check's CNOT order and the 12 CX layers of each block (a proper edge coloring, no data qubit twice in a layer) were found by a SAT solver (CaDiCaL via python-sat) with the static constraints that every cost-2 set has hook cost at least 6 and every cost-3 set at least 5, and lazy constraints: after each solution, every combination of two to four such sets plus data errors reaching a nontrivial logical at fewer than 8 faults was located exactly by a meet-in-the-middle search over syndrome-and-logical keys and forbidden as a clause. Both blocks were admitted within 4 iterations; this code's hook costs are high enough that the full distance is reachable, where the same construction stops at 7 for [[64,18,8]] (notes/64-18-8.md).

Witnesses. The committed circuit.d_circ witnesses were constructed from the analysis: in the Z memory a double-flagged hook (ancilla fault plus the two flag-measurement flips) and the 5 data errors that complete its weight-3 remaining support to a logical; in the X memory a two-hook window on one ancilla (2 faults) and the 6 data errors that complete its weight-2 error set. Both are checked against the derived detector error models with the verifier's GF(2) witness check. A measured logical error rate is NOT recorded in circuit.ler, and cannot be: the pinned BP+OSD decoder takes about 20 s per shot on these 51,000-mechanism detector error models, the tier's PR-time replica budget of 120 s per basis buys about 25 shots, and the admissibility rule rejects a point CI cannot replicate within budget (the 26 entries with a measured rate on the board all have d <= 5 and under about 7,000 mechanisms per memory). At p = 0.01 and p = 0.002 the 8-round memory is saturated (28 of 28 and 37 of 40 shots fail). The following is a local measurement that is inadmissible to the tier, not only outside it: 560 shots per basis is below the tier's 10,000-shot floor (MIN_SHOTS in verify/ler_tools.py) on top of the replica-budget problem, so these numbers must not be copied into circuit.ler. At p = 0.001 with the pinned decoder (seed 7, 4 workers): Z memory 116 failures in 560 shots, per-round rate 0.0323 [0.0263, 0.0398]; X memory 122 failures in 560 shots, per-round rate 0.0345 [0.0282, 0.0424] (Wilson 95% intervals, per-round conversion as in verify/ler_tools.py). A 10-minute RIS search per basis on the committed detector error models finds nothing lighter than 8 (lightest found: 9 in the X memory, 8 in the Z memory).

The scheduling scripts (hook-cost oracle, SAT scheduler, two-flag builder, witness constructor) are local staging output of this contribution and are not committed here; the method above is meant to be enough to rewrite them.
