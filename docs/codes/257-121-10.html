[[257,121,10]] — dyadic CAMEL QD-LDPC code with an all-one column (w = 17)

Direction & hypothesis

This entry imports code D1 of the dyadic CAMEL construction of A. Baldelli, M. Battaglioni, J. Mandelbaum, S. Miao and L. Schmalen, *Quantum CSS LDPC Codes based on Dyadic Matrices for Belief Propagation-based Decoding* (ISIT 2026). It builds on CAMEL (Cycle Assembling and Mitigating EnsembLe decoding) of S. Miao, J. Mandelbaum, H. Jäkel and L. Schmalen, *A joint code and belief propagation decoder design for quantum LDPC codes* (ISIT 2024).

The dyadic construction builds two binary matrices H1 and H2 from dyadic permutation blocks with H1 H2^T = J, the all-ones matrix, over GF(2). It restores commutation by appending one all-one column to both: H_X = [H1 | 1], H_Z = [H2 | 1].

The cell is weight-9plus x unrestricted on the CSS board: the all-one column raises the check weight from 16 to 17, and the code has no layout. No board entry has n <= 257, k >= 121, d >= 10 and w <= 17, so the code is a new frontier point. It beats [[281,121,4]] (w = 21, hypergraph product) on n, d and w. It does not beat [[254,126,14]] (w = 30) on n, k or d, and that entry does not beat it on w, so both stay on the frontier.

The nearest same-cell neighbours are the quasi-dyadic [[256,120,12]] and [[256,120,10]] (both w = 16). They are better on n and w, and [[256,120,12]] is also better on d, so this code stays on the frontier only through k = 121 > 120. kd^2/n = 47.1, which is not the criterion here.

What was searched

No search. The matrices are taken verbatim from the constructors' repository, github.com/AlessioBaldelli99/UnivPM-KIT @ 886501f, folder PCMs/CAMEL_codes/QD-LDPC [[257,121]], files QD_CAMEL_[[257,121]]_H_X.csv and QD_CAMEL_[[257,121]]_H_Z.csv (dense 0/1, one row per check). They were read from the pinned git blobs, cross-checked against the alist copies in the same folder, and written as an npz with keys hx and hz. The conversion asserts:

  • shape 112 x 257 on each side;
  • H_X H_Z^T = 0 over GF(2), rank 68 per side, so k = 257 - 68 - 68 = 121;
  • every check has weight 17;
  • the combined Tanner graph is connected;
  • column 256 is all ones;
  • every 16 x 16 block of the first 256 columns is a dyadic permutation matrix, and H1 H2^T = J.

Witnesses: make_submission in research/kit/submit.py ran 20,000 RIS trials per side (numpy backend; seed 1 for X, seed 2 for Z) and found weight-10 logicals on both sides.

Evidence trail

Gate (research/kit/coordination.py gate):

  • passed;
  • cell weight-9plus x unrestricted;
  • sector distances X = Z = 10, witness weight 10;
  • no lighter logical in 8,000 fresh RIS trials;
  • no exact duplicate and no WL-equivalent entry on the board;
  • board_advancing: true, advancing on d, n and w; not a d-only gain.

Deep ladder (research/audits/leader_audit.py ladder, gf2_fast accelerator, pair depth 64, fresh seeds; lightest logical found, min over sides):

| accelerator trials per side | fresh seeds | lightest logical found | | ---: | :---: | ---: | | 200,000 | 101, 102 | 10, 10 | | 1,000,000 | 201, 202 | 10, 10 | | 2,000,000 | 301, 302 | 10, 10 |

The ladder is flat at 10 on every rung (verdict "holds"). It found weight-10 logicals each time and never a lighter one.

Independent corroboration from the constructors' data in the same commit: their codeword lists words_QD_CAMEL[[257,121]]_H_X.CW and words_QD_CAMEL[[257,121]]_H_Z.CW contain no codeword of ker H_X or ker H_Z below weight 10. They list 3,205 and 3,186 words of weight 10, and every listed weight-10 word is a nontrivial logical (outside the row space of the other check matrix).

For a CSS code d = min(d_X, d_Z), and the nontrivial X-type and Z-type logicals lie in ker H_Z and ker H_X, so d is at least the smaller of the two classical minimum distances. If that enumeration is complete below weight 10, it gives d >= 10, matching the witnesses. Completeness is not established here, so the claim stays an upper bound.

Final claim: d <= 10 on both sides, as a witness-backed upper bound (confidence: upper_bound).
