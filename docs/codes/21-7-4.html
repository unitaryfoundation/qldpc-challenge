[[21,7,4]] — weight-6 Z7-invariant non-CSS stabilizer code

Direction & hypothesis

On the general-stabilizer board, the weight-6 cells at small blocklength (n <= 36) had no rate-1/3 entries with d >= 4, and local-2d-single × weight-6 held 12 entries. Following the group-invariant lazy-SAT approach used for codes/16-4-4-s.json (and the group-based non-CSS LDPC framing of Camara, Ollivier, and Tillich, arXiv:quant-ph/0502086, alongside the low-weight small-code tables of Wei, Han, He, Li, and Liu, arXiv:2601.19848), we tested whether 3 qubit orbits and 2 generator orbits under Z7 admit a connected, genuinely non-CSS, weight-6 stabilizer code with exact distance d = 4 (k = 7, rate 1/3, kd^2/n = 5.333) and a single-layer 2D integer-grid layout within interaction radius 4.0.

What was searched

  • Shape (b, c) = (3, 2) under cyclic groups Z_m (n = 3m, 2m generators, k >= m, generator weight <= 6, minimum generator weight >= 3).
  • Encoding: CaDiCaL 1.9.5 (via PySAT) with exact symplectic commutation (A B^T + B A^T = 0 over GF(2)), symmetry breaking (X or Y on qubit 0 in generator 0, at least one Y entry), and upfront distinct nonzero syndrome constraints for all single-qubit Paulis and all weight-2 Pauli pairs modulo Z_m, so every returned model already has exact distance >= 3 without wasting lazy rounds on weight-1 or weight-2 logicals.
  • Lazy cuts: each round exhaustively enumerates low-weight nontrivial logicals of weight 3 via meet-in-the-middle syndrome hashing and adds up to 24 group-invariant anticommutation cuts at once.
  • For Z7 (n = 21, k = 7, w <= 6, d >= 4): CNF had 6,951 variables and 26,436 clauses (built in 0.01 s); CaDiCaL found this code in 125 lazy rounds (14.43 s on one CPU thread).
  • Companion runs in the same sweep also found [[18,6,4]] (Z6, 10.45 s) and [[24,8,4]] (Z8, 0.96 s) at weight 6, and [[24,6,4]] (Z6, 6.62 s) and [[28,7,4]] (Z7, 4.71 s) at weight 5.
  • Layout: simulated annealing over integer 2D single-layer coordinates on a 5×5 grid (25,000 swap steps, up to 3 seeds) minimized the maximum check diameter to 4.0 (local-2d-single).

Evidence trail

Two independent exact checks confirm d = 4 for these 14 generators:

1. Exhaustive Pauli enumeration (weights 1 to 4): 0 nontrivial logicals of weight 1, 0 of weight 2, 0 of weight 3, and 147 nontrivial logicals of weight 4, including the stored witness X1 Y3 Z5 Z6 (X = [1, 3], Z = [3, 5, 6]). 2. Integer linear programming (SciPy HiGHS MILP): minimizing Pauli weight sum_q max(x_q, z_q) over ker(B | A) across all 2k = 14 logical sectors independently proves exact minimum weight d = 4.

| Verification method | Budget | Lightest nontrivial logical | |---|---:|---| | Exhaustive enumeration (weights 1–3, then 4) | exact (all Paulis w <= 3, plus pair-pair w = 4) | 4 (0 logicals of weight 1, 2, or 3; 147 of weight 4) | | HiGHS MILP (all 14 logical sectors) | exact (proven optimal) | 4 | | verify/validate_candidate.py (RIS refutation gate) | 3,340 RIS trials (seed 1747264672) | 4 (not refuted) |

Stabilizer structure: all 2^14 - 1 = 16,383 non-identity stabilizer group elements were enumerated; the minimum stabilizer weight is 6 (exactly the 14 weight-6 generators, with 0 elements of weight <= 5), so the code is nondegenerate. Every generator has weight 6 and every qubit has check degree 4 (a (4, 6)-regular code).

Claim: d = 4, filed with confidence: "upper_bound" because the board's server-side exact certifier does not yet minimize Pauli weight. Non-CSS: verify/qldpc_verify.py confirms no single-qubit Clifford frame maps the generators to pure X/Z (stabilizer_code_is_not_css and stabilizer_code_is_not_locally_css both pass).

Board-relative placement: verify/validate_candidate.py returns passed: true, board_advancing: true, dominated_by: [], d_only_gain: false, exact_duplicate_of: null, and wl_equivalent_of: null. Literature novelty is not claimed (provenance.novelty: "unknown"); without a generator-weight cap, codetables.de achieves [[21,7,5]].

Dead ends

  • At w <= 5 for the same rate-1/3 shape (Z6 [[18,6,4]] and Z7 [[21,7,4]]), CaDiCaL timed out at 30 s (127 and 111 lazy rounds of weight-3 cuts) without finding a d >= 4 solution.
  • Pushing to d >= 5 at w <= 6 for [[20,5,5]] (Z5, b=4, c=3), [[20,4,5]] (Z4, b=5, c=4), [[24,6,5]] (Z6, b=4, c=3), and [[25,5,5]] (Z5, b=5, c=4) timed out at 60 s each (though [[20,4,5]] and [[24,6,5]] reached rounds with only weight-4 logicals remaining).
  • Weight-4 targets at d >= 4 ([[14,2,4]], [[16,2,4]], [[18,3,4]], [[20,4,4]]) timed out at 30–45 s each in the same session.

Tools

  • Model: Gemini 4 (Antigravity harness), directed by @joacibb.
  • Software: Python 3.12, NumPy, SciPy (HiGHS MILP), PySAT (cadical195), ldpc (BP+OSD sanity check), and the repository's verify/qldpc_verify.py and verify/validate_candidate.py.
  • Compute: ~14.4 s single-core CPU for the [[21,7,4]] SAT synthesis, < 5 s for exact MILP + exhaustive verification and 2D layout annealing (under 0.01 CPU-hours for this code).

Reproduction

Index the 21 qubits as 7*b + g (b in {0, 1, 2}, g in Z_7). The cyclic shift by t in Z_7 maps 7*b + g -> 7*b + ((g + t) mod 7). The 14 independent generators in codes/21-7-4.json are the 7 translates (t = 0..6) of two weight-6 Pauli representatives:

  • Orbit 0 (checks.S rows 0–6): Y0 X1 Z2 Z6 X7 Y13 (YXZIIIZXIIIIIYIIIIIII)
  • Orbit 1 (checks.S rows 7–13): X9 Y10 Z16 Z17 Z19 X20 (IIIIIIIIIXYIIIIIZZIZX)

The single-layer 2D coordinates (layers = 1, interaction_radius = 4.0) are stored directly in codes/21-7-4.json under locality.coordinates.
