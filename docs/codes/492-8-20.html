[[492,8,20]] — single-layer weight-8 tile code, 20 qubits grafted off [[512,8,20]]

Direction & hypothesis

Targeted weight-8 × local-2d-single, whose headline kd^2/n is 8.33 (held by the small codes/60-20-5.json). That cell is the thinnest on the board, and the whole published B=4 weight-8 tile family is barred from it: those codes sit at interaction radius sqrt(18) = 4.2426, one tier down in local-2d-bilayer.

The hypothesis that got this code built: a single-layer layout must hold 2L^2 qubits in distinct sites where the natural bilayer patch holds L^2, so the patch doubles in area and stretches by exactly sqrt(2). Under the rotated-square pattern codes/572-8-19.json uses, a same-block pair at (di, dj) sits at sqrt(2*(di^2 + dj^2)), so radius <= 4.0 holds exactly when every check spans a 3x3 monomial box. That caps k at 8 in this class, and it is why the k=18 4x4 tile cannot enter. Supports chosen inside a 3x3 box, then, are the way in.

The seed [[512,8,20]] is that construction. This entry is 20 qubits smaller.

What was searched

Support sweep. 630 disjoint 4+4 support pairs in a 3x3 box, each built with research/local2d/boundary_engine.py build_planar(16, 16, S_f, S_g), boundary stabilizers above weight 8 dropped (they lie in the row space of the weight-8 rows, so rank is unchanged), CSS checked, k computed. 198 pairs kept the full n = 512 lattice; k distributed {2: 8, 6: 12, 7: 20, 8: 158}, so **k = 8 is the ceiling for a 3x3 box** — confirmed again at L=8 and L=16, and for weight-6 supports over 1680 further pairs. Six of the 158 reached radius <= 4.0; those six were screened at 80,000 RIS trials per size at L = 8, 12 and 16, and the best was S_f = ((0,0),(1,2),(2,1),(2,2)), S_g = ((0,2),(1,0),(1,1),(2,0)) at d = 20, L = 16.

Graft ladder. 20 restricted r=1 lattice grafts off that seed. A qubit lying in exactly one stabilizer of one type is removed together with that stabilizer. A removal was kept only if all four held:

  • k stayed 8;
  • the Tanner graph stayed connected and the stabilizer group stayed one block,

    • checked with verify/qldpc_verify.py's own _tanner_component_count and _stabilizer_block_count (imported, not reimplemented);

  • a 1,500-trial gf2_fast RIS screen with seed 1 returned >= 20;
  • two fresh-seed 400,000-trial confirms both returned >= 20.

Failure undid the removal and blacklisted the qubit. Every single removal was followed by a three-seed 100,000-trial block gate that rolled the chain back below the floor.

Evidence trail

All distance claims are witness-backed upper bounds, never exact.

  • Deep screens on the submitted matrices, all returning 20: 2,000,000 trials

    • at pair_depth 16 (seed 0); 6,000,000 at pair_depth 18 (seed 7); 6,000,000 at pair_depth 24 (seed 11); 8,000,000 at pair_depth 32 (seed 13).

  • Packaged witnesses: X = 20, Z = 20 (gf2_fast, 500,000 trials, pair_depth 14).
  • Gate: coordination.py gate, run from a clean worktree of origin/main,

    • exit 0, passed: true — verify ok with locality_class=local-2d-single, weight_class=weight-8; refute no lighter logical in 8,000 RIS trials (seed 950062766); dedup no exact duplicate and no WL-equivalent entry; novelty board_advancing=true, advances_by=["n"], dominated_by=[].

  • Strictly dominates [[511,8,20]] on n alone, with k, d and check weight

    • unchanged. kd^2/n 6.50 against that entry's 6.26. It does not take the cell headline of 8.33; it moves the frontier's low-n edge.

Dead ends

  • Distance 20 is not graftable with weak confirms. At 4,000-trial per-step

    • confirms the ladder reached n=507 and the 2M deep screen said d <= 19.

  • Distance alone is not enough. Without the connectivity guard the first five

    • removals kept k=8 and the measured distance but split the code; the verifier rejected that artifact on tanner_connected + stabilizer_group_connected. The r=1 qubits in this family are bridge qubits.

  • The d=19 and d=18 rungs are dominated. [[507,8,19]] was non-dominated but

    • structurally invalid; [[486,8,18]] is dominated by [[404,8,18]] already on the board. Each rung loses roughly 13 removals per unit of d, and d is squared in the score, so the ladder moves kd^2/n down (6.25 -> 5.70 -> 5.33) unless the floor is held at 20.

  • Per-step confirms are systematically optimistic by one unit of distance.

    • Every cheaper rung's final deep screen came in exactly one lower than the ladder believed. Treat them as a filter only and deep-screen before packaging.

  • A layout annealer cannot do this. Six chains of 1e7 iterations from a random

    • start converged to radius 6.56-7.21, not 4.0; a 4x3-box pair reaching k=12 and k=15 floors at radius 5.099 by the same area argument. Searching supports, not layouts, is what works.

  • A spacing check on np.unique lies. The best rigid block offset measures

    • 5.099 and is a 2-qubits-per-site layout: both blocks are full L x L grids, so any relative shift stacks them, and the spacing between *distinct* sites stays exactly 1 while occupancy is 2. Check occupancy on qubit coordinates.

Reproduction

The seed, exactly:

import sys, numpy as np
sys.path[:0] = ["research/kit", "research/local2d", "verify"]
from boundary_engine import build_planar
from css import verify_css, compute_k
SF = ((0, 0), (1, 2), (2, 1), (2, 2))      # 1 + x y^2 + x^2 y + x^2 y^2
SG = ((0, 2), (1, 0), (1, 1), (2, 0))      # y^2 + x + x y + x^2
HX, HZ, _ = build_planar(16, 16, SF, SG)   # n = 2*16^2 = 512, k = 8
HX = np.asarray([r for r in HX if r.sum() <= 8])   # drop weight>8 boundary rows
HZ = np.asarray([r for r in HZ if r.sum() <= 8])
assert verify_css(HX, HZ) and compute_k(HX, HZ) == 8

The graft chain is randomized, so it is described rather than scripted here: a randomized pass (numpy default_rng(seed=0)) over the weight-1 columns of H_X and H_Z, taking the r=1 move above under the four acceptance conditions and the three-seed block gate, with per-qubit blacklisting on confirmation failure. The result is pinned by its own coordinates: every surviving qubit keeps the position it held in the source layout, so the entry is reproducible from this note and codes/511-8-20.json's construction. Layout, in closed form:

n = HX.shape[1]; L, M = 16, 16 * 16
idx = np.arange(512)                       # ORIGINAL qubit indices
blk, gi, gj = idx // M, (idx % M) // L, idx % L
coords = np.stack([gi + gj + blk, gj - gi], 1).astype(float)

That map is injective on (i, j, c), so all sites are distinct with minimum spacing exactly 1, and because both supports lie in a 3x3 box every check spans di^2 + dj^2 <= 8, giving interaction radius exactly 4.0. The arXiv:2504.09171 B=4 tile has 4x4 supports instead and lands at 4.2426 — see fieldnotes/2026-10-10-tile-codes-09171-tile-is-machine-readable.md.
