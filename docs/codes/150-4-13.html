How this code was found

[[150,4,13]] two-block code over C75 from the Bicycle Race census (arXiv:2610.13880), rebuilt from the paper's database

Direction & hypothesis

arXiv:2610.13880 (Gideon Lee, "Bicycle Race: small two-block codes on the Pareto frontier", 9 October 2026) enumerates about 10^8 two-block group-algebra codes C(a,b) of check weight five to nine over groups of order at most 160 (n <= 320), with exact distances, and publishes a database of 12,448 of them (github.com/gideonlsx/bicycle-race @ aed705a, file data/codes.jsonl, CC BY 4.0), each with a witness logical. The question here is narrow: which of the codes the paper tabulates (Tables 2, 3, 9 and 11, and the ones named in Sec. 3) advance the board's four-axis frontier (n, k, d, check weight) and are not already on it? This entry is one of the 28 that do.

What was searched

  • Screen: the 45 distinct parameter triples in those tables were compared

    • with every CSS entry on main under the site's Pareto rule (an entry dominates when n <=, k >=, d >=, w <= with at least one strict), at the paper's check weight. Thirteen are already on the board at the same or a lower weight ([[60,4,8]], [[64,18,8]], [[84,14,10]], [[90,8,10]], [[90,12,9]], [[102,20,10]], [[144,12,12]], [[180,8,16]], [[182,6,18]], [[186,10,14]], [[192,8,16]], [[288,12,18]] and [[288,16,16]]); four are dominated by board entries ([[168,12,12]] by [[144,12,12]], [[198,8,16]] by [[180,8,16]], [[200,16,12]] by [[192,16,12]], and [[216,4,16]] by [[192,4,16]]); Table 9's [[192,12,14]] and [[192,16,12]] are Lin-Pryadko archive codes, not in the paper's database, and already on the board. The remaining 28 are new nondominated points and are filed one per PR.

  • This code: record 4a55958ff6cb5166 of the database (Table 11 of the paper;

    • database labels front, front-2D), over the cyclic group C75 (GAP SmallGroup(75,1)), check weight 5 (block weights 3 + 2): a = 1 + x + x^53, b = 1 + x^36 in a generator x of order 75, i.e. the generalized bicycle code with A = a(x), B = b(x). The stored matrices use the qubit ordering of the paper's database (record 4a55958ff6cb5166, github.com/gideonlsx/bicycle-race @ aed705a, data/codes.jsonl, CC BY 4.0): qubits 0..74 are the left block and 75..149 the right block, group elements numbered as GAP's Elements(SmallGroup(75,1)) with e0 the identity, x = e5, so a = e0 + e5 + e31, b = e0 + e17.

  • Rebuild: the generators' right-multiplication permutations in the

    • database's data/groups.jsonl give the multiplication table; then H_X = (L(a) | R(b)), H_Z = (R(b)^T | L(a)^T) with qubits 0..|G|-1 the left block. A short standalone NumPy script did this and checked CSS commutation, k = n - rank H_X - rank H_Z = 4, max check weight 5, and both of the paper's witnesses (weight 13 X, weight 13 Z, in the kernel of the other side's checks and outside its own stabilizer row space) before anything was submitted.

  • Distance: the paper states d = 13 exactly. Its record: d_X "ladder in the screen (frontier mode, exact_on_accept; cluster engine, symmetry roots)";

    • d_Z "ladder in the screen (frontier mode, exact_on_accept; cluster engine, symmetry roots)"; verification "one engine". Here, qldpc submit's own search (20,000 NumPy RIS trials per side, then a 2,000,000-trial accelerator pass) read d_X <= 13 and d_Z <= 13, and the verifier's refutation search found nothing lighter than 13.

Claim: d <= 13 on both sides, a witnessed upper bound agreeing with the paper's exact distance. An exact certificate (verify/certify.py) is the maintainer-side tier and is not asserted here.

Dead ends

  • The 17 tabulated codes listed above add nothing to the board and were not

    • filed.

  • Only the tabulated codes were screened. The database's 2,435 codes labelled

    • as lying on the paper's own front are a larger pool a later pass could screen against the board the same way.

Tools

Claude Fable 5.1 (Claude Code): a standalone NumPy rebuild script (the construction above, from the database's group data), cli/qldpc.py submit for the witness search, the verifier and the PR draft, and verify/qldpc_verify.py on the final JSON.

Reproduction

Clone github.com/gideonlsx/bicycle-race @ aed705a and run its scripts/codes.py on record 4a55958ff6cb5166: it rebuilds the code from data/groups.jsonl and data/codes.jsonl and checks the witnesses in pure Python. Or build it from the construction above. The JSON here carries both check matrices and both witnesses, so the entry verifies without the download.
