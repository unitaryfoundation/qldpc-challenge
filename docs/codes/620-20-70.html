[[620,20,70]] — Two-block group algebra (2BGA) code on a non-abelian metacyclic group

Direction & hypothesis

Targeted the 2bga-coset family. The board's best entry in this family ([[684,10,90]], kd^2/n=118.42) had only 33 submissions total, far fewer than generalized-bicycle (707 submissions) -- the family looked under-explored relative to its potential, since 2BGA generalizes generalized-bicycle's circulant construction to non-abelian groups (left/right regular representations always commute, for any group, so CSS orthogonality holds without an abelian requirement). Hypothesis: a systematic sweep over non-abelian metacyclic groups, not just the affine groups the existing entries used, could beat the family record.

What was searched

Swept 486 metacyclic groups C_m |x_r C_t (semidirect products of cyclic groups, m from 6 to 260, r chosen so ord(r,m)=t, with 2*m*t<=1000), 6 random weight-{4,5,6,7,8} group-algebra element pairs (a,b) per group, screened at 150 RIS trials/side using this repository's own search engine (verify/heuristic_distance.py::ris_min_logical). Top candidates by estimated kd^2/n were then deepened with parallel RIS (4-8 worker processes, 1500-2500 trials/worker/side, i.e. 6000-20000 trials/side total).

An early version of the sweep allowed n up to 1000 and found much stronger-looking candidates (e.g. n=930, weight-16, kd^2/n~900 at 150 trials), but these were rejected by this repository's own schema cap: verify/qldpc_verify.py::admissible() only allows n in (700,1000] when max check weight <= 8 and claimed d <= 40 -- our weight-16, d~170 candidates did not qualify. The sweep was corrected to n<=700 (where the cap is unrestricted) and re-run from there.

Correction (2026-10-03)

Initial submission claimed d_X=104 from this repository's own RIS engine (verify/heuristic_distance.py::ris_min_logical, copied locally, 20,000 trials, 8 parallel workers, pure Python). The CI verify gate (which uses the gf2_fast C++ accelerator, 8,000,000 trials) found a lighter X-logical of weight 96, refuting the d=104 claim. This environment does not have gf2_fast installed, so our own search had a far smaller effective budget than the CI gate's. Updated the claim to d_X=96 using the CI-provided witness directly (independently verified here: it lies in ker(H_Z) and is not in rowspace(H_X), confirming it is a genuine X-type logical of weight 96). d_Z=107 is unchanged (not refuted). New score: kd^2/n = 20*96*96/620 = 297.29. This is not a construction error -- it reflects the RIS search budget gap between this environment and the CI gate's accelerated path, the same dynamic that applies to every upper_bound entry on this board.

Second correction (2026-10-03, at review)

The reviewer ran the single-block annihilator attack of #2364 and #2365 on the entry. With H_X = [L(a) | R(b)], a vector supported in the right block alone commutes with every X check iff R(b) annihilates it, and that annihilator is a 51-dimensional subspace; information-set decoding inside it finds a weight-70 Z logical at iteration 303, stable through 40,000 iterations with a second seed. The same search in ker(L(a)) on the left block finds a weight-84 X logical. Both were re-verified independently of the search (in the kernel of the opposite-type checks, outside the same-type row space). The entry is therefore [[620,20,70]], kd^2/n = 20*70*70/620 = 158.06. Uniform RIS at 8,000,000 trials did not reach either vector; the attack is structural to two-block constructions and the subspace is small enough that it should be part of any 2BGA search before a distance is claimed.
