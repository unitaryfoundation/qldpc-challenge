[[392,18,28]] — weight-8 bivariate bicycle code on Z_28 x Z_7

Direction & hypothesis

Cell weight-8 x unrestricted, CSS board, n between 360 and 400. Before this filing the weight-8 frontier there ran 360-10-28, 364-8-32, 372-14-29, 376-98-8, 378-32-19, 378-18-27, 390-10-32, 392-102-14 and 392-8-33: at n <= 392 every weight-8 entry with k >= 18 had d <= 27 (378-18-27), and every entry with d >= 28 had k <= 14. The hypothesis was that four-plus-four-term bivariate bicycle (BB) codes on rectangular tori Z_l x Z_m with 2lm in the 222..400 band could put a k = 18, d = 28 point there. [[392,18,28]] does: no board entry has n <= 392, k >= 18, d >= 28 and check weight <= 8, and the k - 2 margin holds ([[392,16,28]] is not dominated either). It is not a d-only gain (no board entry has the same n, k and weight).

What was searched

Random-support BB codes H_X = [A | B], H_Z = [B^T | A^T] with A and B four monomials each, both containing 1 (no loss of generality), on every torus Z_l x Z_m with l >= m >= 3 and 222 <= 2lm <= 400, the torus drawn uniformly from that list and the other three monomials of each polynomial uniformly from the torus.

Random supports rarely give k >= 16, so the sweep ran a parallel generate-and-rank prefilter: 200,000 draws (seed 72), of which 927 had k >= 16 and a connected Tanner graph (research/kit/prescreen.block_structure). Those went through research/kit/search.screen with the gf2_fast backend at 400 trials; 16 advanced the board frontier at screen depth and were confirmed at 20,000 / 200,000 / 2,000,000 fast trials (research/kit/surrogate.distance_rand_witness, pair depth 8), dropping a candidate as soon as its running bound stopped advancing. Screen-depth bounds at this weight are badly optimistic (this code screened at 44); 13 of the 16 fell below the 336-24-24 / 378-18-27 staircase during confirmation. The survivors were this code, a [[384,16,30]] on Z_24 x Z_8 (handled separately) and a [[384,16,28]] that the latter dominates.
