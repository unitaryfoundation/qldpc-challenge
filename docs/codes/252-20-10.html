[[252,20,10]] — two-block group-algebra code over C21 ⋊ C6 (= C21 x S3)

Direction & hypothesis

Cell weight-6 x unrestricted, CSS board, n between 221 and 300. The weight-6 frontier there ran 224-18-12, 224-12-16, 234-26-7, 240-16-14, 254-14-16, 270-30-7, 288-16-16, 288-12-18, 294-10-20: at n <= 300 every weight-6 entry with k >= 20 had d <= 7, and every one with d >= 10 had k <= 18. The hypothesis was that two-block group-algebra (2BGA) codes on non-abelian groups of order 111 to 150 could put a k = 20, d = 10 point into that corner at check weight 6. [[252,20,10]] does: no board entry has n <= 252, k >= 20, d >= 10 and check weight <= 6.

What was searched

Random-support 2BGA codes H_X = [L(a) | R(b)], H_Z = [R(b)^T | L(a)^T] with a, b three group elements each, both containing the identity (no loss of generality: multiplying a or b by a group element permutes qubits and checks). The group menu was every non-abelian group of order 111 to 200 the kit builds from Cayley-table constructors: dihedral D_n, metacyclic C_n ⋊_r C_k (up to two actions r per (n, k)), C_m x D_k, C_m x A4, C_m x S4, C_m x A5, D_a x D_b, C_m x (C_n ⋊ C_k) for eight small metacyclic factors, S5, and the split metacyclic presentations ZSZ(l1, l2, q) of research/kit/nonabelian_lp.py.

Random supports almost never give usable k (a generic weight-3 element is invertible on the higher-dimensional irreducible blocks of F_2[G]), so the sweep ran a parallel k prefilter: 200,000 draws at 222 <= n <= 400 (seed 51), of which 198,731 had k < 14 and 888 were direct sums; the k histogram of the 381 kept was 14:90, 16:159, 18:49, 20:38, 24:37, 28:3, 32:3, 44:2. Those 381 went through research/kit/search.screen with the gf2_fast backend at 400 trials; 6 advanced the board frontier at screen depth and were confirmed at 20,000 / 200,000 / 2,000,000 fast trials (research/kit/surrogate.distance_rand_witness, pair depth 8). A second sweep of 400,000 draws restricted to 222 <= n <= 300 with k >= 16 (seed 61) found the same (n, k, d) point on two further presentations of the same order-126 group, which is what one expects when the code is a property of the group rather than of the draw.

Reproduction

The group is research/kit/nonabelian_lp.py's zsz(21, 6, 8), i.e. research/kit/group_algebra.py's metacyclic(21, 6, 8): C_21 ⋊ C_6 with y x y^-1 = x^8, element x^i y^j at index 6 i + j, identity at 0. Since 8 = -1 mod 3 and 8 = 1 mod 7, the action inverts the 3-part of C_21 and fixes the 7-part, so the group is C_21 x S_3 (order 126). With x = (1, 0), y = (0, 1):

a = 1 + x^8 + x^20 y^3 (indices 0, 48, 123), b = 1 + x^11 y^2 + x^19 y^4 (indices 0, 68, 118).

import sys; sys.path[:0] = ["research/kit", "verify"]
from nonabelian_lp import zsz
from group_algebra import build_2bga
from css import compute_k
mul = zsz(21, 6, 8)
HX, HZ = build_2bga(mul, [0, 48, 123], [0, 68, 118])   # n = 252, k = 20
assert compute_k(HX, HZ) == 20

Check sets match codes/252-20-10.json row for row in this order. Witness search: `surrogate.distance_rand_witness(HX, HZ, trials=2_000_000, seed=51000003 + 2_000_000, backend="fast", pair_depth=8)` returns a weight-10 logical; the numpy lightest_logical at 1,500 trials with seeds 51 (X) and 52 (Z) gives the two witnesses in the JSON.
