[[23,5,5]] — weight-6 Z6-invariant mixed-orbit non-CSS stabilizer code

Direction & hypothesis

Uniform-orbit cyclic (b, c) = (3, 2) stabilizer codes (n = 3m, 2m independent generators, as in codes/21-7-4.json) fix the encoding rate at k/n = 1/3, giving kd^2/n = 16/3 = 5.333 at d = 4. To explore d = 5 codes with w <= 6 and kd^2/n > 5.333 that still admit a compact single-layer 2D embedding (layers = 1, interaction_radius <= 4.0), we generalized the cyclic lazy-SAT construction to mixed-orbit Z_G actions whose qubit orbits have sizes dividing G. For G = Z_6 acting on five orbits of sizes [6, 6, 6, 3, 2] (n = 23 qubits) with c = 3 generator orbits (18 generators), full rank yields k = 5, so d = 5 gives kd^2/n = 5 * 25 / 23 = 5.435 at a blocklength small enough to pack tightly on a single planar layer.

What was searched

  • Mixed-orbit Z_G-invariant non-CSS stabilizer templates (w in {5, 6}, d >= 4 or d >= 5) across cyclic groups Z_3 through Z_8 with divisor sub-orbits, using 6-worker clause-shuffled multi-seed portfolios of CaDiCaL 1.9.5 and CaDiCaL 1.5.3 via PySAT (50–55 s timeout per target, 5,000-conflict slices per incremental check).
  • Encoding: exact symplectic commutation over GF(2), symmetry breaking (X or Y on qubit 0 in generator 0; at least one Y entry overall), upfront distinct-syndrome constraints banning all weight-1 and weight-2 Paulis modulo Z_G, and orbit-deduplicated lazy cuts (up to 64 cuts per round via meet-in-the-middle syndrome hashing) banning nontrivial logicals up to weight d_target - 1.
  • For Z_6 with orbits [6, 6, 6, 3, 2] (n = 23, c = 3, d_target = 5, w in {5, 6}): CNF had 11,148 variables and 41,780 clauses; cadical195 (seed 303) returned this code in 60 lazy rounds (55.0 s).
  • Layout: bug-free simulated annealing on a compact unit triangular lattice (min_spacing = 1.0001, 150,000 swap/move steps, 8 seeds) followed by scale-invariant power-mean continuous ratio polishing (L-BFGS-B) achieved layers = 1, min_spacing = 1.0001, interaction_radius = 3.605912 (g = 4 k d^2 / (n r^4) = 0.1286).

Evidence trail

Two independent exact checks certify d = 5 for these 18 generators:

1. Exhaustive Pauli enumeration (weights 1 to 4): meet-in-the-middle syndrome hashing over all Paulis of weight 1, 2, 3, and 4 confirms 0 nontrivial logicals of weight <= 4. 2. Integer linear programming (SciPy HiGHS MILP): minimizing Pauli weight sum_q max(x_q, z_q) over ker(B | A) across all 2k = 10 logical sectors independently proves exact minimum weight d = 5 (proved = True), matching the stored weight-5 witness Z2 Y7 Z8 X10 Z15 (X = [7, 10], Z = [2, 7, 8, 15]).

Stabilizer structure: all 2^18 - 1 = 262,143 non-identity stabilizer group elements were enumerated; the minimum stabilizer weight is 6 (exactly the 18 weight-6 generators, with 0 elements of weight <= 5), so the code is nondegenerate. Every generator has weight 6; qubit check degrees are 6 on orbit 0 (qubits 0–5) and orbit 4 (qubits 21–22), and 4 on orbits 1–3 (qubits 6–20).

Claim: d = 5, filed with confidence: "upper_bound" because the board's server-side certifier does not yet minimize non-CSS Pauli weight. Non-CSS: verify/qldpc_verify.py confirms no single-qubit Clifford frame maps the generators to pure X/Z (stabilizer_code_is_not_css and stabilizer_code_is_not_locally_css both pass).

Board-relative placement: verify/validate_candidate.py returns passed: true, board_advancing: true, dominated_by: [], d_only_gain: false, exact_duplicate_of: null, and wl_equivalent_of: null in cell weight-6 x local-2d-single (stabilizer). Literature novelty is not claimed (provenance.novelty: "unknown"); without a check-weight cap, codetables.de reaches higher distance/dimension at n = 23.

Dead ends

  • Mixed-orbit d = 4 targets Z_6 [6,6,3,3,1] ([[19,7,4]]), Z_6 [6,6,3,2,2] ([[19,7,4]]), Z_4 [4,4,4,4,2,1] ([[19,7,4]]), and Z_8 [8,8,4,4,1] ([[25,9,4]]) were proven UNSAT in < 5 s each.
  • Mixed-orbit targets Z_6 [6,6,6,1] ([[19,7,4]]), Z_5 [5,5,5,1] ([[16,6,4]]), Z_6 [6,6,6,2] ([[20,8,4]]), Z_7 [7,7,7,1] ([[22,8,4]]), Z_8 [8,8,8,1] ([[25,9,4]]), Z_5 [5,5,5,5,1] ([[21,6,5]]), and Z_4 [4,4,4,4,4,1] ([[21,5,5]]) timed out at 45–55 s per 6-core portfolio without reaching d_target.
  • Parallel algebraic sweeps over 1-block and 2-block twisted GF(4) Abelian codes (n = 14..36), non-Abelian 1-block and two-sided lifted-product GF(4) codes (n = 12..32), and exhaustive GF(4) cyclic/constacyclic codes (n = 14..22) found [[36,6,6]] weight-6 codes (Z_6 x Z_6, Z_4 x Z_9, Z_2 x Z_3 x Z_6, Z_3 x Z_6), none of which embedded within r <= 4.0 on a single layer (best valid 1-layer radius after cutting 6 redundant checks was r = 4.076 on Z_4 x Z_9).

Reproduction

Partition the 23 qubits into five Z_6-orbits:

  • Orbit 0 (size 6): indices 0..5
  • Orbit 1 (size 6): indices 6..11
  • Orbit 2 (size 6): indices 12..17
  • Orbit 3 (size 3): indices 18..20
  • Orbit 4 (size 2): indices 21..22

For t in {0, 1, 2, 3, 4, 5}, shift t maps qubit base + j inside an orbit of size s to base + ((j + t) mod s). The 18 independent weight-6 generators in codes/23-5-5.json are the 6 translates (t = 0..5) of three base representatives:

  • Family 0 (checks.S rows 0–5): X0 X2 Y8 Z15 Y18 Z21
  • Family 1 (checks.S rows 6–11): Y4 Z5 Z12 X17 Z19 X22
  • Family 2 (checks.S rows 12–17): Z0 Y2 Z6 Z7 X10 Y14

The single-layer 2D coordinates (layers = 1, min_spacing = 1.0001, interaction_radius = 3.605912) are stored directly in codes/23-5-5.json under locality.coordinates.
