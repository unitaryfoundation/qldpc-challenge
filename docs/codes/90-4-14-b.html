[[90,4,14]] — abelian 2BGA code on Z_9 x Z_5, a = [0, 20, 42], b = [0, 29, 30, 33, 35]

Direction & hypothesis

Track cell: unrestricted x weight-8 (max check weight 8). Target: a point with n' <= 90, k' >= 4, d' >= 14 at check weight <= 8 that no board entry occupies. This code gains on d, k, n, w against [[100,4,14]] (w=8, codes/100-4-14.json), [[104,4,14]] (w=8, codes/104-4-14.json), [[90,4,14]] (w=9, codes/90-4-14.json), [[92,2,14]] (w=8, codes/92-2-14.json), [[92,4,13]] (w=8, codes/92-4-13.json), [[96,2,14]] (w=8, codes/96-2-14.json). Nearest board points at n' <= 90: [[88,2,14]] (w=8), [[88,4,13]] (w=8), [[80,6,12]] (w=8), [[72,4,12]] (w=8).

Hypothesis: below n = 110 the board's weight-6 two-block entries are close to exhaustive, but abelian two-block group-algebra (2BGA) codes with larger or unequal supports (|a|, |b| between 2 and 6, check weight 7 to 10) are sampled far more thinly, and every abelian group of a given order (not only cyclic groups and two-factor tori) is a separate family. Two earlier independent seeds over equal 4+4 and 5+5 supports kept producing non-dominated points, so this run used fresh seeds and added the unequal 2+5, 3+4, 3+5, 3+6, 4+5 and 4+6 shapes. Board-relative novelty is from verify/validate_candidate.py; literature novelty is unverified (Lin-Pryadko's 2BGA tables, arXiv:2306.16400, and the bivariate-bicycle literature cover many small abelian groups, and this instance may be in them). Slug note: the board already holds codes/90-4-14.json, a different code with the same [[90,4,14]] but max check weight 9; this one has max check weight 8, so it is filed as 90-4-14-b.

What was searched

H_X = [L(a) | R(b)], H_Z = [R(b)^T | L(a)^T] over F_2[G] with G = Z_9 x Z_5 (|G| = 45) built as group_algebra.cyclic_product(9, 5): elements are the tuples in itertools.product order, index = position in that order (identity = 0). a = [0, 20, 42] and b = [0, 29, 30, 33, 35] are lists of element indices (|a| = 3, |b| = 5, check weight 8). G is abelian, so L(a) and R(b) are commuting multivariate circulants (a bivariate-bicycle-type code when G has two factors).

Sweep (research/kit group_algebra.build_2bga, css.compute_k, surrogate.distance_rand with backend gf2_fast, one thread per candidate, 10-18 worker processes):

  • every abelian group of order 14..55 (n = 2|G| <= 110), supports 3+5 (200,000 random pairs per group), 2+5 (50,000 random pairs per group), 3+6 (60,000 random pairs per group), 4+6 (40,000 random pairs per group), identity in both a and b, seed 8111: 26,600,000 candidates built, 2,552,095 with k >= 3, each read at 40 gf2_fast RIS trials against the board's best d at that (n, k, weight) (our own open PRs counted as board entries); 1,152 survivors re-read at 400 trials, 758 unique non-dominated records; refinement (at most 3 per distinct (n, k, d, w)) 20,000 trials: 92 of 92 still advancing, 200,000 trials: 92 of 92 still advancing, 2,000,000 trials: 92 of 92 still advancing.

Left or right translation of a or b is a qubit relabelling, so fixing the identity in both loses nothing. Every screening reading is an upper bound on d, so the funnel can only discard a candidate whose true distance is also non-advancing.
