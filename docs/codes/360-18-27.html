[[360,18,27]] — weight-8 bivariate bicycle code on Z_60 x Z_3

Direction & hypothesis

Cell weight-8 x unrestricted, CSS board, n between 330 and 380. Before this campaign the weight-8 frontier there ran 330-10-27, 336-28-20, 336-24-24, 350-8-29, 360-10-28, 364-8-32, 372-14-29 and 378-18-27: no weight-8 entry with n <= 360 and k >= 18 had d above 24. The hypothesis was that four-plus-four-term bivariate bicycle (BB) codes on long thin tori (Z_60 x Z_3 and similar) could put a k = 18 point near d = 27 below n = 378. [[360,18,27]] does: no board entry has n <= 360, k >= 18, d >= 27 and check weight <= 8, and the d - 2 margin holds ([[360,18,25]] is not dominated either). It is not a d-only gain (no board entry has the same n, k and weight), and it complements the [[360,16,28]] filed from the same campaign (two more logicals, distance one lower).

What was searched

Random-support BB codes H_X = [A | B], H_Z = [B^T | A^T] with A and B four monomials each, both containing 1 (no loss of generality), on every torus Z_l x Z_m with l >= m >= 3 and 300 <= 2lm <= 400, the torus drawn uniformly from that list and the other three monomials of each polynomial uniformly from the torus.

Random supports rarely give k >= 16, so the sweep ran a parallel generate-and-rank prefilter: 300,000 draws (seed 92), of which 1,338 had k >= 16 and a connected Tanner graph (research/kit/prescreen.block_structure). Those went through research/kit/search.screen with the gf2_fast backend at 400 trials; 33 advanced the board frontier at screen depth and were confirmed at 20,000 / 200,000 / 2,000,000 fast trials (research/kit/surrogate.distance_rand_witness, pair depth 8), dropping a candidate as soon as its running bound stopped advancing and skipping any already dominated by a point staged earlier in the campaign. Three were staged: this code, a [[378,26,26]] on Z_21 x Z_9 (filed separately) and a [[378,18,29]] on Z_63 x Z_3.
