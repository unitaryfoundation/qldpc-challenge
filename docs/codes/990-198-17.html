[[990,198,17]] — irregular pair-partition CPM code with weight-7 checks, rate 1/5, lift P = 99

Direction & hypothesis

Cell: CSS, unrestricted, weight 7, extended tier (n <= 1000 with w <= 8 and d <= 40). The pair-partition (PP) construction of Okada and Kasai (arXiv:2607.14091) gives CSS orthogonality from paired-difference equations on CPM exponents; they apply it to complete J x L templates, where every check has weight L. The weight-8 (3,8) entries on the board use it at rate about 1/4. Lee, Okada, Maskara, Kasai and Zhou (arXiv:2609.30069) count the design rate as R = 1 - J_tot/L_stab and name quantum-compatible irregular templates as a natural direction. Hypothesis: a sparse, irregular template with every check of weight 7 can keep a design rate near 1/5 and reach d >= 15, which at k/n = 1/5 gives kd^2/n >= 45, above the best weight-7 entries on the board (codes/682-20-38.json and codes/762-28-32.json by @FarLab, two-block group-algebra codes in the sense of arXiv:2306.16400, kd^2/n 42.3 and 37.6). This code: 198 * 17^2 / 990 = 57.8.

Frontier: The board files this code in its weight-8 class (max check weight <= 8), where it is not near the leaders; among entries with max check weight <= 7 the highest kd^2/n on the board today is 42.3 (codes/682-20-38.json), and this entry's is 57.8 (d = 17; the board shows d <= 17; this code is outside verify/certify.py's current envelope (CONTRIBUTING.md), so the exact value is our evidence, not a certificate).

Technique (not ours): the pair-partition rule, its pairing arrays and the CPM lift are Okada and Kasai's (arXiv:2607.14091); the design-rate count and the permanent-vector upper bound (App. A there) are from Lee, Okada, Maskara, Kasai and Zhou (arXiv:2609.30069), whose outlook names irregular templates as a direction; quasi-cyclic CSS LDPC codes from circulant permutation matrices go back to Hagiwara and Imai (arXiv:quant-ph/0701020), and CSS pairs of two irregular LDPC codes were analysed by Hagiwara and Imai (arXiv:0801.1361).

Board precedents: the same commutation mechanism at weight 8 on the complete (3,8) template: codes/904-230-22.json, codes/712-182-20.json and codes/632-162-18.json by @vprusso, codes/824-210-20.json by @MathysRennela, codes/808-206-20.json by @pandey-tushar, codes/568-146-18.json by @nihoniumqc, our codes/928-238-22.json and codes/976-250-22.json, and the published codes/584-150-18.json (Okada and Kasai); @vprusso's entries also cite the lifted-product construction of Panteleev and Kalachev (arXiv:2111.03654). This entry does not reuse any of their exponent arrays.

Also builds on: the exhaustive distance search builds on Okada and Kasai's cpm_distance (MIT licence); ours is the GF(2)-verified automorphism roots.

Prior-art check (2026-10-22): arXiv:2607.14091, arXiv:2609.30069, the Okada-Kasai project page and web searches; we did not find a pair-partition code on an irregular template or with check weight below 8. On the board, the weight <= 7 entries with k/n >= 0.15 have kd^2/n at most 10.8. Literature novelty is not claimed (novelty: unknown).

Our contribution: the irregular 4 x 10 template A, the template census that selected it, the pairing choice, the lift P = 99 and this exponent draw, the distance screening below and the exact-distance computation.

What was searched

Templates. One side's templates (J block rows x L block columns, columns of degree 2 or 3, rows of weight <= 7) were enumerated exhaustively up to row and column permutation for J = 3 and 4; X/Z pairs whose row overlaps all have even size were placed by SAT and ranked by rate x (permanent-vector upper bound)^2, where the bound is our generalisation of App. A of arXiv:2609.30069 to sparse templates (a ranking aid for a generic abelian lift, not a distance proof). Ranges: (J_X, J_Z) = (3,3) at L = 7..10, (3,4) at L = 8..11, (4,4) at L = 9..12; (5,5) at L = 12..15 was only sampled. Best ranked: template A ((4,4), L = 10, bound 22 on both sides, rate 1/5). A (4,4), L = 9 template with bound 24 (rate 1/9) has two equal rows and admitted no 4-cycle-free pairing; the next, B, had bound 16 and screened at d <= 12.

Template A (block columns of each block row). X: [0,2,3,4,5,6,7], [0,2,3,4,5,8,9], [1,2,3,6,7,8,9], [1,4,5,6,7,8,9]. Z: [0,2,3,4,5,6,8], [0,2,3,4,5,7,9], [1,2,5,6,7,8,9], [1,3,4,6,7,8,9]. Columns 0 and 1 have degree 2, columns 2..9 degree 3, on both sides.

Pairings and lifts. An anneal over pairings (one pair partition per X-row / Z-row overlap; target: no forced 4-cycles, largest solution space of the paired-difference equations) gave about 220 distinct 4-cycle-free pairings for template A (11 + 22 + 188 in three rounds). Each was built at P = 97 and screened with Stern, 3 s per side; 14 of them went to a P scan, P = 90..100, 2 exponent draws each: 308 codes, Stern 3 s per side, then 60 s per side for d >= 16, then 3 x 300 s per side for d = 17. Lightest found over that scan (at the 60 s rung where run, else 3 s): 4..8 (x12), 9..11 (x65), 12..13 (x94), 14..15 (x86), 16 (x44), 17 (x7). Rate is exactly 1/5 at every P (no extra dependencies), so all seven 17s (from 4 pairings; each also 17 in 3 x 300 s per side) score 57.8. No 18 was seen. This one (P = 99) is the one taken through the board heuristic; the other six are not filed.

Exact distance

d_X = d_Z = 17 by exhaustive search with gexact, our C++ extension of the branch-and-bound in Okada and Kasai's cpm_distance (github.com/kasaikenta/pair-partition-cpm-css-codes, MIT licence). Their method, per side: grow a support from a root column; branch on the unsatisfied check with the fewest free columns; forbid a finished branch's column in its later siblings; prune with ceil(unsat / max column degree) and a greedy packing of disjoint free sets; stop at a kernel word. Our changes: (a) roots from an automorphism group whose generators are verified over GF(2) (every X row maps into span(H_X), every Z row into span(H_Z)); here the Z_99 shift inside each block column, 10 orbits with smallest columns r_0 < ... < r_9. Any logical can be mapped by an automorphism to contain r_j, j the first orbit it meets, so root j searches only supports that contain r_j and lie in orbits j, j+1, ... (orbit forbidding). (b) An extra set-cover bound (off in cpm_distance's mode). No run hit its time limit.

| run, per side | X | Z | |---|---|---| | decide, weight <= 16, Z_99 roots | none | none | | minimum, weight <= 17, Z_99 roots | 17 | 17 | | decide <= 16, no automorphisms (every column a root) | none | none | | decide <= 16, gexact in cpm_distance's mode (its roots and lower bound) | none | none |

The minimum run's weight-17 words and the filed witnesses re-check as logicals. Known-answer tests: on 20 small codes of the same template (Z_P, P = 4..8, n = 40..80; 40 side cases, d 2..6, half odd) gexact agreed with the run without automorphisms in every case, and with a brute-force search by weight for n <= 60 (24 cases). Cost: 5 to 11 CPU-s per side and run with Z_99 roots, about 5 CPU-min per side without. These are computations by separate programs developed with AI assistance, not a certificate.

Dead ends

  • Pairings with the largest solution space (5 free dimensions) all carry a

    • forced weight-5 logical through the two degree-2 columns, at every P; the 4-cycle test does not see it, a 3 s Stern screen does.

  • Templates with a 3-row side: the bound is <= 11 once the side has an

    • empty cell; the complete 3 x 7 template has odd row overlaps (7), so no pair partition exists.

  • Weight 6: no template with J <= 4 (J = 5 sampled) reaches kd^2/n = 40 even at the bound.
