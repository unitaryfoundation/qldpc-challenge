[[340,18,26]] — weight-8 bivariate bicycle code on Z_34 x Z_5

Direction & hypothesis

Cell weight-8 x unrestricted, CSS board, n between 300 and 360. Before this campaign the weight-8 frontier there ran 300-12-25, 306-26-19, 308-10-26, 310-12-26, 330-10-27, 336-28-20, 336-24-24 and 350-8-29: at n <= 340 every weight-8 entry with d >= 26 had k <= 12, and every entry with k >= 18 had d <= 24. The hypothesis was that four-plus-four-term bivariate bicycle (BB) codes on tori with 2lm in 300..400, prefiltered for k >= 18, could put a k = 18 point at d = 26 there. [[340,18,26]] does: no board entry has n <= 340, k >= 18, d >= 26 and check weight <= 8, and the k - 2 margin holds ([[340,16,26]] is not dominated either). It is not a d-only gain (no board entry has the same n, k and weight).

What was searched

Random-support BB codes H_X = [A | B], H_Z = [B^T | A^T] with A and B four monomials each, both containing 1 (no loss of generality), on every torus Z_l x Z_m with l >= m >= 3 and 300 <= 2lm <= 400, the torus drawn uniformly from that list and the other three monomials of each polynomial uniformly from the torus.

Random supports rarely give k >= 18, so the sweep ran a parallel generate-and-rank prefilter: 300,000 draws (seed 111), of which 710 had k >= 18 and a connected Tanner graph (research/kit/prescreen.block_structure). Those went through research/kit/search.screen with the gf2_fast backend at 400 trials; 8 advanced the board frontier at screen depth and were confirmed at 20,000 / 200,000 / 2,000,000 fast trials (research/kit/surrogate.distance_rand_witness, pair depth 8), dropping a candidate as soon as its running bound stopped advancing and skipping any already dominated by a point staged earlier in the campaign. Two were staged: this code and a [[392,22,28]] on Z_14 x Z_14 (filed separately).
