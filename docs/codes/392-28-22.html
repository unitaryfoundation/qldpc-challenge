[[392,28,22]] — weight-8 bivariate bicycle code on Z_14 x Z_14

Direction & hypothesis

Cell weight-8 x unrestricted, CSS board, n between 330 and 400. Before this campaign the weight-8 frontier there ran 336-88-12, 336-28-20, 336-24-24, 376-98-8, 378-32-19, 378-18-27 and 392-102-14: no weight-8 entry with n <= 392 and k >= 28 had d above 20. The hypothesis was that four-plus-four-term bivariate bicycle (BB) codes on square tori could add distance at k = 28. [[392,28,22]] does: no board entry has n <= 392, k >= 28, d >= 22 and check weight <= 8. It is a narrow step (it does not hold at k - 2 or d - 2) and not a d-only gain (no board entry has the same n, k and weight). It sits next to the [[378,26,26]] filed from the same campaign (two more logicals, distance four lower, 14 more qubits).

What was searched

Random-support BB codes H_X = [A | B], H_Z = [B^T | A^T] with A and B four monomials each, both containing 1 (no loss of generality), on every torus Z_l x Z_m with l >= m >= 3 and 222 <= 2lm <= 400, the torus drawn uniformly from that list and the other three monomials of each polynomial uniformly from the torus.

Random supports rarely give k >= 16, so the sweep ran a parallel generate-and-rank prefilter: 300,000 draws (seed 101), of which 1,284 had k >= 16 and a connected Tanner graph (research/kit/prescreen.block_structure). Those went through research/kit/search.screen with the gf2_fast backend at 400 trials; 24 advanced the board frontier at screen depth and were confirmed at 20,000 / 200,000 / 2,000,000 fast trials (research/kit/surrogate.distance_rand_witness, pair depth 8), dropping a candidate as soon as its running bound stopped advancing and skipping any already dominated by a point staged earlier in the campaign (several were dominated by this campaign's own [[378,26,26]], [[384,16,30]] and [[392,18,28]]). This was the only one staged.
