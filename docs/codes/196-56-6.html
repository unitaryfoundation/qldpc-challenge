[[196,56,6]] weight-12 CSS tensor amplification

The submitted JSON records witness-backed upper bounds on both distances. Randomized search is not a lower-bound certificate.

Direction & hypothesis

Target: CSS weight-9plus x unrestricted. Explore the rate, blocklength and check-weight tradeoffs of small-factor CSS tensor products. This applies an established construction; literature novelty remains unverified.

What was searched

Seven tensor instances were built after screening small board seeds and parity factors; all seven passed the original trusted gate and six were retained as non-dominated within the batch. Initial pilots used 500 NumPy trials per side. The confirmation ladder below starts with the subsequent 100,000-trial confirmation and includes the fresh million-trial rung. Final validation uses upstream da1f2c0a1611b215376b249c139f4951e2394418.

Evidence trail

Confirmation ladder for the submitted code, each rung a fresh seed unless marked otherwise, reading the lightest logical found:

| budget (trials/side) | lightest logical | | ---: | ---: | | 100,000 (C++; root seed 20961004; threads=2, pair_depth=16) | 6 | | 1,000,000 (C++; root seed 21061005; threads=4, pair_depth=16) | 6 |

2 fresh-seed rung(s) agree at the best bound, the deepest of them at 1,000,000 trials per side. The submitted witness reproduces it: X: d <= 6 (upper_bound), Z: d <= 6 (upper_bound).

The first accelerated confirmation used 100,000 trials per side, 2 threads and pair_depth=16. The final rung uses 1,000,000 trials per side and 4 threads. Each accelerated call searches both Pauli sides and returns the overall minimum, rather than separate minima. Root seeds differ between calls; within a call the backend uses matching thread-seed offsets across sides. NumPy and C++ trial budgets are not interchangeable. Returned witnesses were saved and checked. No smaller logical was found in these rungs. Both submitted sides remain witness-backed upper bounds.

The 12-qubit factor is not a single all-ones parity amplifier. No matching lower-bound proof for this product is supplied; only the witnessed upper bounds are claimed.

Dead ends

  • The tested 466-qubit tensor product was excluded because the 414-qubit

    • product dominates it in blocklength, encoded dimension and check weight.

  • A previous amplification fieldnote rejected three products for

    • noncommutation; reconstructing the general tensor blocks gives commuting checks. Rank conditions affect the homology dimension, not the square-zero differential identity.

Reproduction

Input entries are codes/12-8-2.json and codes/15-7-3.json at upstream commit da1f2c0a1611b215376b249c139f4951e2394418. Input attribution: 12-8-2: @MathysRennela; 15-7-3: @FarLab. The 6-qubit factor is the known all-ones error-detecting CSS code. The 8- and 12-qubit factors, when used, are board reproductions of the 2BGA construction (arXiv:2306.16400). The 32-qubit seed is a SAT search result, the 20-qubit seed is a self-orthogonal CSS search result, and the 15-qubit seed is the standard quantum Hamming code. Only the two named inputs are used in this submission; their stored layout coordinates are not inherited.

The following code reconstructs the submitted checks, including their ordering:

import json
import numpy as np

def read(name):
    with open("codes/" + name) as f:
        doc = json.load(f)
    result = []
    for side in ("X", "Z"):
        h = np.zeros((len(doc["checks"][side]), doc["n"]), dtype=np.int8)
        for i, support in enumerate(doc["checks"][side]):
            h[i, support] = 1
        result.append(h)
    return result

matrices = read('12-8-2.json') + read('15-7-3.json')
rows = [[0, 2], [0, 2], [0, 1, 2, 3], [0, 1, 2, 3]]
hx, hz, gx, gz = [h[r] for h, r in zip(matrices, rows)]
mx, nq = hx.shape
mz = hz.shape[0]
ax, na = gx.shape
az = gz.shape[0]
I = lambda d: np.eye(d, dtype=np.int8)
Z = lambda r, c: np.zeros((r, c), dtype=np.int8)
HX = np.block([
    [np.kron(hx, I(na)), Z(mx*na, mz*ax), np.kron(I(mx), gz.T)],
    [np.kron(I(nq), gx), np.kron(hz.T, I(ax)), Z(nq*ax, mx*az)]])
HZ = np.block([
    [np.kron(hz, I(na)), np.kron(I(mz), gx.T), Z(mz*na, mx*az)],
    [np.kron(I(nq), gz), Z(nq*az, mz*ax), np.kron(hx.T, I(az))]])

The X/Z matrices have shapes (78, 196) and (78, 196) and GF(2) ranks 70 and 70. Therefore k=196-70-70=56; maximum check weight is 12.
