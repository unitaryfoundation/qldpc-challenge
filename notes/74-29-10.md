# [[74,29,10]] — random Clifford encoder, expurgated; d proved by exhaustive search

Source: github.com/MarinAndreGirard/qubit-stabilizer-codes-2026 @ 930cc7c, code `round2-004`, file `codes/stabilizers/n074_k029_d10.txt`.
All paths in backticks below refer to that repository.

## Direction & hypothesis

Aim: dense, high-rate stabilizer codes at short length that beat the best known codes in Grassl's tables
(codetables.de), not a low-weight cell. Hypothesis: a random stabilizer code has, on average,
E = 2^-(n-K) * sum_(w<d) C(n,w) 3^w nonzero logical classes of weight below d. When E is a few hundred, adding a few
logical operators to the stabilizer removes all of them at a cost of only a few logical qubits once E is below a few
thousand (each added operator removes about half of the remaining classes, and there are many choices of operators). At its (n, k) the codetables.de lower bound on 4 Nov 2026 is
9 (upper bound 16); this code has d = 10. On this board it lands in the unrestricted / any-weight
cell.

## What was searched

Parent: a random Clifford encoder (16-20 layers of random two-qubit Clifford gates on random qubit pairs) on 34
logical inputs and 40 ancillas gives an [[74,34]] code. For these parameters E is about 2072. All logical
classes of weight below 10 were enumerated exactly (the meet-in-the-middle enumeration described below), and 5
logical operators were added as stabilizers. They were chosen by a randomized GF(2) search so that every low-weight
class anticommutes with at least one of them, which removes it: d(S') >= D iff every low-weight class lies outside
the symplectic complement of the added subspace U, or in U itself. Result: [[74,29,10]].

This code is one of 192 from the same campaign (October 2026, n = 53-254, d = 5-13), every one above the
codetables.de lower bound at its (n, k). Method, statistics and a first-moment model of where the method wins are
in `note/note.pdf`.

Check weight: the expurgated generators are dense (max weight 56). For this submission the same stabilizer group
was given a lighter generating set by an information-set search: random qubit order, reduced row echelon form over
the interleaved (x_q, z_q) columns, keep every reduced row and every sum of two rows, 3,000 rounds, then a greedy
basis by ascending weight (which minimizes the largest generator weight among the vectors found). Max weight
56 -> 27. The row space is unchanged; anyone can check it against `codes/stabilizers/n074_k029_d10.txt`.

## Evidence trail

The distance is proved, not only witnessed.

- Upper bound: the witness in this entry is a nontrivial logical operator of Pauli weight 10
  (`codes/witnesses.csv`).
- Lower bound: write any Pauli of weight <= 9 as a product of two pieces of weight <= 4 and <= 5; a logical
  operator gives two pieces with equal syndromes. The original certifier (`c2`, run on the Aurora supercomputer at
  ALCF) enumerated all 94,975,486 Paulis of weight <= 4 and all 3,914,429,652 of weight 5, checked every equal-syndrome pair
  exactly, and found no nontrivial logical. The visited counts equal the closed form
  sum_(w<=4) C(74,w) 3^w + C(74,5) 3^5 (`verify/results/original_certifier_runs.csv`).
  The run was on the code rebuilt from its recipe.
- The release's independent certifier (`verify/certify_distance.py`) has not been run on this code; its certificate is the original one above.
- Hence d = 10 exactly. The confidence is filed as `exact`; the board's verifier records it as an upper bound until
  its own certifier runs.

The search accepted a code only on a complete certificate of this kind, so no sampled distance estimate enters the
claim. In control runs at D = d + 1 on 30 other codes of the campaign, the same kind of certifier found a logical of
weight d, as it should.

## Dead ends

From the same campaign (details in `note/note.pdf`, section "Role of AI agents"):

- Structured parents (quasi-cyclic and translation-invariant encoder circuits): as many low-weight logical classes
  as random parents at the parameters tested.
- Tensor networks of random few-qubit codes and concatenation trees: useful controls, never reached the table.
- Parents built from [[4,2,2]] blocks: about five times more low-weight classes than random parents at n = 32;
  none of four led to a certified code, against four of four for random parents.
- Editing published codes (removing generators, adding others) exposed weight-1 or weight-2 logical operators.
- For this board: a random [[n,k]] stabilizer group has fewer than one expected element of weight <= 32 once n is
  around 97 or more at these rates, so only the 12 shortest of the 192 codes fit the weight cap. The best basis
  found for [[100,37,13]] has max weight 37.

## Tools

Search and certification programs written and run by AI coding agents under the author's direction; heavy
enumeration on Aurora (ALCF). Independent checker and certifier in `verify/` (plain Python and numba). The
low-weight basis search is about 100 lines of plain Python and takes seconds per code.

## Reproduction

`codes/stabilizers/n074_k029_d10.txt` holds the expurgated generators; `provenance/recipes/n074_k029_d10.json.gz` holds the encoder recipe and
seed that generated the parent. `python3 verify/check_codes.py` re-checks every code and witness;
`python3 verify/certify_distance.py codes/stabilizers/n074_k029_d10.txt` re-proves d >= 10.
