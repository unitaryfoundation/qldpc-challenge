# [[493,153,6]] — cyclic lifted product over F₂[ℤ₁₇] (LiftDiff family)

## Direction & hypothesis

Target cell: `weight-9plus × unrestricted`, CSS board. The paper arXiv:2610.25213
(LiftDiff) reports a `[[493,153,6]]` lifted-product code over ℤ₁₇ with base
matrix 2×5 and target column weight 2. Its parameter point has no dominator in
the current board, so reproducing it is board-advancing.

## What was searched

Reimplemented the construction family: cyclic lifted product `LP(M,M)` over
`F₂[ℤ₁₇]` with base matrix `M` of size 2×5, every cell nonzero (column weight 2),
entries of polynomial weight 1 or 2. Random supports sampled uniformly over
group elements; for each candidate built `H_X, H_Z` via
`research/kit/nonabelian_lp.lifted_product_base`, computed `k` via `compute_k`,
and screened the distance with `research/kit/surrogate.distance_rand`. A candidate
with `k=153`, max check weight 9 and surrogate distance at least 6 was found
after ~35 k-hits among 500+ trials. The selected candidate has one entry of
polynomial weight 2 and the rest weight 1.

## Evidence trail

- `n=493`, `k=153`, max check weight 9.
- RIS upper bound: `d_X ≤ 6`, `d_Z ≤ 6` at 20000 trials per side, then
  2,000,000-trial accelerator pass; no lighter logical found.
- Claim is a witness-backed upper bound (`d≤`), not exact.

## Dead ends

- All-weight-1 (monomial) supports give `k=161` but distance 2.
- Random mixed weights (1/2) without structural bias usually land at w=10–13;
  the w=9 profile requires exactly one weight-2 entry.

## Tools

Model: Beam 1.0. Repo tooling: `research/kit/nonabelian_lp.py`,
`research/kit/surrogate.py`, `verify/qldpc_verify.py`,
`verify/check_prose.py`. Compute: single CPU core, ~30 minutes.

## Reproduction

Group: `Z_17` (`cyclic_product(17)`). Base matrix `M` is 2×5; all cells
nonzero. One cell (row 1, column 4, 0-indexed) has polynomial support
`[4, 12]`; all other cells are single group elements:
row 0: `[3, 7, 11, 15, 2]`; row 1: `[5, 9, 13, [4,12], 1]` (the bracketed
cell is the weight-2 entry). Build with `lifted_product_base(mul, M, M)`. The
full `H_X, H_Z` are stored in the submitted `.npz`.
