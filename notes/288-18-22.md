# [[288,18,22]] — weight-8 bivariate bicycle code on Z_12 x Z_12

## Direction & hypothesis

Cell `weight-8 x unrestricted`, CSS board, n between 248 and 292. Before
this filing the weight-8 frontier there ran 248-24-18, 248-16-22,
252-26-18, 252-22-19, 252-20-21, 270-34-14, 270-10-24, 288-12-24 and
292-22-23: at n <= 288 no weight-8 entry with k >= 18 reached d = 22 (the
closest were 252-20-21 and 248-16-22). The hypothesis was that
four-plus-four-term bivariate bicycle (BB) codes on square tori, which
the prefiltered random sweep reaches often at k = 16..20, could fill that
step. [[288,18,22]] does: no board entry has n <= 288, k >= 18, d >= 22
and check weight <= 8. It is a narrow step (it does not hold at k - 2 or
d - 2), and against the board's 288-18-20 (also a weight-8 BB code on
Z_12 x Z_12, same n, k and weight) the gain is d-only. The gate flagged
the two as possibly equivalent (same Weisfeiler-Leman signature) and asked
for a matched-depth re-measurement, which is in the evidence trail below:
at the same budget the peer reads 20 and this code reads 22, so they are
not equivalent and the distance gap is real at that depth.

## What was searched

Random-support BB codes H_X = [A | B], H_Z = [B^T | A^T] with A and B four
monomials each, both containing 1 (no loss of generality), on every torus
Z_l x Z_m with l >= m >= 3 and 222 <= 2lm <= 400, the torus drawn uniformly
from that list and the other three monomials of each polynomial uniformly
from the torus.

Random supports rarely give k >= 16 (about 0.4 to 0.5% of draws), so the
sweep ran a parallel generate-and-rank prefilter: 300,000 draws (seed 82,
30 prefilter processes), keeping those with k >= 16 and a connected Tanner
graph (research/kit/prescreen.block_structure). The survivors went through
research/kit/search.screen with the gf2_fast backend at 400 trials, and the
ones that advanced the board frontier at screen depth were confirmed at
20,000 / 200,000 / 2,000,000 fast trials
(research/kit/surrogate.distance_rand_witness, pair depth 8), dropping a
candidate as soon as its running bound stopped advancing, and skipping any
candidate already dominated by a point staged earlier in the campaign. This
sweep staged three codes: this one, a [[392,20,26]] on Z_14 x Z_14 and a
[[360,16,27]] on Z_60 x Z_3 (dominated by a later [[360,16,28]]).

`verify/validate_candidate.py` (through research/kit/coordination.py's gate

caution against 288-18-20 described above. Literature
novelty is unverified; board-relative novelty comes from
verify/validate_candidate.py (fingerprint and Weisfeiler-Leman dedup
against every board entry found nothing).

## Dead ends

- Earlier prefiltered 4 + 4 BB sweeps (100,000 and 200,000 draws) gave the
  separately filed [[240,20,18]], [[320,16,24]], [[384,16,30]] and
  [[392,18,28]]; their n = 250..300 survivors all fell under 248-16-22 /
  252-20-21 / 292-22-23.
- Cyclic generalized-bicycle codes with a designed divisor g | x^m - 1,
  weight-4 a and b (check weight 8): weight-4 multiples of g exist only for
  deg g <= ~22 at odd m from 111 to 200, and 4,000 such draws gave nothing
  advancing even at 400 trials.
- Random-support 2BGA on non-abelian groups at check weight 8, 16,000
  serial plus 150,000 prefiltered draws: every screen-depth survivor
  collapsed by 20,000 trials (dominated by 248-24-18, 252-26-18,
  292-22-23, 336-24-24, 378-18-27).

## Reproduction

Torus Z_12 x Z_12 (x and y of order 12), terms (i, j) = x^i y^j:

A = 1 + x^4 y^9 + x^7 y^11 + x^8 y^11,
B = 1 + y^3 + y^10 + x^5 y^7.

```python
import sys; sys.path[:0] = ["research/kit", "verify"]
from bb import build_bb
from css import compute_k
HX, HZ = build_bb(12, 12, [(0, 0), (4, 9), (7, 11), (8, 11)],
                  [(0, 0), (0, 3), (0, 10), (5, 7)])   # n = 288
assert compute_k(HX, HZ) == 18
```

Check sets match codes/288-18-22.json row for row in this order. The numpy
`surrogate.lightest_logical` at 1,500 trials with seeds 82 (X side, pass
(HX, HZ)) and 83 (Z side, pass (HZ, HX)) returns a weight-22 logical on
each side.
