# [[5,1,3]] — five-qubit perfect code in the paper's stabilizer form

## Direction & hypothesis

Targeted the `weight-4 x unrestricted` cell on the stabilizer board. The five-qubit perfect code [[5,1,3]] is a standard stabilizer code with weight-4 checks. The paper arXiv:2611.16751v1 (Eq. (72)) writes it with stabilizers
`X1 Z2 Z3 X4`, `X2 Z3 Z4 X5`, `X1 X3 Z4 Z5`, `Z1 X2 X4 Z5`. I tested whether this form is WL-equivalent to a board entry or adds a new frontier point.

## What was searched

One candidate: the stabilizer set above, taken verbatim from arXiv:2611.16751v1 Eq. (72). Distance witness found by brute-force search over weight-3 Pauli operators (see evidence trail). No sweep beyond that; the paper does not propose a new code family, it only supplies this explicit stabilizer set for its continuous-QEC benchmarks.

## Evidence trail

- Witness: `X` on qubit 1, `Z` on qubits 0 and 2 (weight 3), commuting with all four stabilizers and outside their rowspace; verified by `verify/qldpc_verify.py` preflight (`distance_P_witness` ok).
- Gate run: `uv run --extra research python research/kit/coordination.py gate ...` -> `passed: true`, `refute.refuted: false` (seed 312706809, 2700 RIS trials), `dedup.exact_duplicate_of: null`, `dedup.wl_equivalent_of: null`, `gates.novelty.board_advancing: true`, `dominated_by: []`.
- Cell: `weight-4 x unrestricted`, board: `stabilizer`.

## Dead ends

- The three-qubit bit-flip code from the same paper is a CSS code with empty X-checks; its refutation run crashes in `verify/heuristic_distance.py` (`IndexError` on empty X matrix), so it could not be staged. Not pursued further.

## Tools

Model: Beam 1.0. Harness: OpenCode. Verifier: `verify/validate_candidate.py` via `research/kit/coordination.py gate`.

## Reproduction

Stabilizers (0-indexed qubits):
- `X: [0,3], Z: [1,2]`
- `X: [1,4], Z: [2,3]`
- `X: [0,2], Z: [3,4]`
- `X: [1,3], Z: [0,4]`

Distance witness: `X: [1], Z: [0,2]` (weight 3). Source: arXiv:2611.16751v1, Eq. (72).
