# [[684,14,78]] affine 2BGA weight-8 code

## Target and result

This campaign targeted the `weight-8 / unrestricted` cell after the previous
`[[684,12,81]]` entry became part of the live board. The new candidate has the
same block length and check-weight cap, but increases the logical-qubit count
to 14 while retaining a deep-RIS distance upper bound of 78.

The operational-efficiency value is

```text
k d^2 / n = 14 * 78^2 / 684 = 124.526
```

The current `[[684,12,81]]` leader has value `115.105`. The candidate is also
not dominated in the Pareto comparison: it has more logical qubits than that
entry, while the current `[[684,8,85]]` point has fewer logical qubits and a
higher distance.

## Construction

The code is a two-block group-algebra CSS construction over

```text
Aff(F_19) = C_19 semidirect C_18,
```

with action `r = 2`. Elements are indexed as `(x exponent)*18 + (y
exponent)`. For supports

```text
a = [6, 289, 76, 217]
b = [294, 337, 142, 284]
```

the checks use commuting left and right regular representations:

```text
H_X = [L(a) | R(b)]
H_Z = [R(b)^T | L(a)^T]
```

The construction gives CSS commutation. Independent verifier recomputation
gives `rank(H_X) = rank(H_Z) = 335`, hence
`k = 684 - 335 - 335 = 14`. Every check has weight 8.

The construction family is described in Lin and Pryadko,
[arXiv:2306.16400](https://arxiv.org/abs/2306.16400).

## Search and distance evidence

The candidate was selected from an archive of affine support mutations. Its
early screen reported `d <= 109`; this was treated as a ranking signal only.
The candidate was then rechecked with fresh compiled RIS searches at increasing
budgets and pair depths:

| trials | pair depth | lightest witnessed weight | side |
| ---: | ---: | ---: | :--- |
| 100,000 | 32 | 86 | X |
| 500,000 | 48 | 82 | Z |
| 1,000,000 | 64 | 84 | X |
| 2,000,000 | 80 | 78 | X |

The JSON records the X-side witness of weight 78 from the deepest run and a
separate Z-side witness of weight 82 from the 500,000-trial run. Both
witnesses were independently checked for membership in the kernel of the
opposite checks and for non-membership in the corresponding stabilizer row
space. The reported distance is therefore the honest upper bound `d <= 78`,
not an exact-distance claim.

## Validation and equivalence review

`verify/qldpc_verify.py` passes the schema, CSS commutation, `n/k`, check
weight, and both witness checks. The clean-board candidate gate reports
`board_advancing: true` for `weight-8 / unrestricted`, with no exact duplicate
and no WL-equivalent board entry. The equivalence review is recorded in
`provenance.notes` as checked against the current board entries and their
published construction data, with no equivalent entry found.
