# [[170,70,8]] halved CPM pair-partition code, (J,L) = (3,10), P = 34

## Direction & hypothesis

Issue #2992 asked for the halved CPM pair-partition codes of arXiv:2609.30069
(Definition 1 with the reversing fold of Proposition 4); its (4,10) family went
onto the board on 2026-10-13 as [[90,21,10]], [[95,22,11]], [[140,31,14]], and
[[200,43,19]]. This entry comes from the follow-on sweep of 2026-10-12 over the
paper's (3,8), (3,10), (4,10), and (4,12) families at the lifts where the
stabilizer board had no entry at all: the paper publishes no generators and its
data repository (`ultra-high-rate-qec/design-principles-data`) was empty on
2026-10-11, so the families were searched directly over their exponent arrays.
For the (3,10) family n = 5P and k = 2P + 2 for every accepted
template, and the distance is whatever the search finds.

## The construction

The parent is a pair-partition CPM code with J = 3 check blocks and L = 10
qubit blocks of size P = 34. X checks come from an exponent array E: row
(j, s) has a 1 at qubit (l, s - E[j][l] mod P) for each l. Z checks come from
D[j][l] = -E[j][l xor 1] mod P in the same way. E must satisfy the paper's
pair-partition rule: each off-diagonal cell (i < j) carries a perfect matching
M on the L block columns, edge-disjoint from the matchings already placed in
its row and column, and E[i,u] + E[j,u xor 1] = E[i,v] + E[j,v xor 1] mod P
for every matched pair {u, v}. The search draws M at random, solves the
resulting homogeneous integer system for E with sympy, and reduces a random
integer combination of the kernel basis mod P.

The reversing fold identifies qubit t of block l with qubit -t mod P of block
l xor 1. Each parent X check then becomes one stabilizer generator on the
5P = 170 surviving qubits (blocks 0, 2, 4, 6, 8): an X leg on each surviving
block's position and a Z leg on each partner position, with coinciding legs
merging to Y. Every generator has weight at most 10. The 3P = 102
generators span a group of rank 3P - 2 = 100, hence
k = 170 - 100 = 70.

## Evidence trail

- Witness: a Pauli logical of weight 8 with X support [54, 138] and Z support
  [59, 99, 100, 110, 130, 143] (positions in both carry Y), stored in the JSON; it commutes with every
  generator and lies outside the stabilizer group, as the gate re-checks.
- Lower bounds: none. The distance is an upper bound from search.
- Accelerator bias: the unframed gf2_fast search on the symplectic doubling
  minimizes |x| + |z|, so a logical with Y legs looks heavier than its Pauli
  weight and can be missed. The frame screen draws a random single-qubit
  symplectic frame per qubit, runs the doubled search, maps each find back,
  and scores it by Pauli weight. On a (4,10), P = 40 code of this family, 12
  frames x 500,000 trials found Pauli weight 15 where 100,000,000 unframed
  trials read 19, so unframed non-refutations of these codes are weak
  evidence, and every count above is framed.
- Gate (`verify/validate_candidate.py` through `research/kit/coordination.py`
  against main c17845a2, 2026-10-15): passed; advances the weight-9plus x unrestricted stabilizer board; literature novelty UNVERIFIED.

## Dead ends

- The paper's instances cannot be rebuilt from the paper: no arrays appear in
  it or its appendices, and the data repository is empty. Where this entry
  falls short of a published value, whether the gap is in the template search
  (the paper does not say how its E were chosen) or in our distance estimate

- Plain Pauli-weight RIS in Python at 1,500 trials ranks templates only
  loosely; the ranking that fed the frame screen came from it, so better

## Reproduction

```python
import numpy as np

def halved_checks(P, E):
    J, L = len(E), len(E[0])
    HX = np.zeros((J * P, L * P), dtype=np.int8)
    for j in range(J):
        for l in range(L):
            for s in range(P):
                HX[j * P + s, l * P + (s - E[j][l]) % P] = 1
    checks = []
    for h in HX:
        x, z = [], []
        for ri, l in enumerate(range(0, L, 2)):
            for t in range(P):
                if h[l * P + t]:
                    x.append(ri * P + t)
                if h[(l ^ 1) * P + (-t) % P]:
                    z.append(ri * P + t)
        checks.append({"X": x, "Z": z})
    return checks

E = [[6, 27, 13, 23, 6, 12, 26, 9, 27, 22], [30, 6, 23, 10, 26, 3, 15, 12, 2, 16], [28, 0, 10, 21, 27, 28, 30, 29, 18, 6]]
S = halved_checks(34, E)   # the 3P generators of codes/170-70-8.json, in order
```
