# [[424,106,20]] — split Pauli-labelled circulant code over Z_53, weight 8, Y-free generators

## Direction & hypothesis

Target: the weight-8, unrestricted cell of the stabilizer board, whose best entry by kd^2/n is [[452,115,18]] (82.4), a
symplectic halving of a CSS pair-partition CPM code. Instead of folding a CSS parent, we built non-CSS quasi-cyclic codes
directly from Pauli-labelled circulant permutation blocks, aiming to keep the distance growth of the (3,8) pair-partition
CPM CSS codes of Okada and Kasai (arXiv:2607.14091). This entry is from the same search as [[488,123,22]] and
[[568,143,22]], one design step below them.

## What was searched

A split Pauli-CPM code over Z_P has 6 row blocks and 8 column blocks; generator (i, s) puts the Pauli Lambda[i][j] in
{X, Z} on qubit j*P + (s + E[i][j]) mod P. Each column block puts X on three row blocks and Z on the other three, with
3-sets that differ between columns, so the generators are Y-free and no single-qubit Clifford makes them all pure. Two row
blocks commute for every P if the columns where their labels differ can be matched in pairs with equal exponent
differences. We searched all 1,690 parity-valid label patterns, solving the pairing equations and rejecting designs that
force weight-1 or weight-2 logicals or short cycles inside an anticommuting 3-row set. This design has no forced harmful 4-cycles and a one-dimensional line
of integer solutions, so each prime lift gives one code up to the relabeling x -> x^u, with k = 2P. Short GPU screens
(20 to 240 s per lift) found witnessed distance 20 at every lift we screened from P = 53 to 113 (P = 53, 59, 71, 83,
97, 101, 103, 107, 109, 113), so kd^2/n = 100 there, and 12 to 16 at the smaller lifts P = 29 to 47. This entry is P = 53, the smallest lift that
reached 20; the larger screened lifts up to P = 113 behave the same.

## Evidence trail

Board claim: **d <= 20, witnessed upper bound.** We have no exact proof and no lower bound for this code; the number is
the lightest logical our searches found. The witness is Y-free and has Pauli weight 20. Searches, none of which found
anything lighter:

- GPU Pauli-weight information-set search with correlated steps, 2400 s (1.5e10 steps): returned 20, with 137,230 hits at that weight;
- fresh-elimination GPU search without correlated steps, 1800 s, 1.7e8 eliminations: returned 20;
- GPU search on the Hamming sectors of the symplectic double, 1500 s: lightest Pauli weight among 865 logicals, 20;
- the repository's `verify/ris_gpu.py` on the 848-qubit symplectic double, 2,000,000 trials, pair depth 32: best weight 20 in both sectors;
- an independent audit with its own seeds: a 600 s correlated-step run (60,187 hits at 20) re-reached 20 and found nothing lighter;
- the repository's own gate, run locally as CI runs it (`verify/gate_changed.py` with the base-branch verifier, seed
  424106020): orbit-fold passes over 13 symmetry-derived partitions, one Python RIS seed of 75,880 trials, and the accelerated
  pass over 6,510,000 trials before its 90-minute cap (lightest proposal 20): no logical lighter than 20.

The symplectic double (H_X = (A|B), H_Z = (B|A)) is a weight-8 CSS code [[848,212]] with distance at least that of
this code; we make no claim of an advantage over CSS codes. Our own symmetry-reweighting searches found nothing to
use beyond the Z_P translations, and at prime P there is no cyclic quotient to attack.

Equivalence checks. The verifier's single-qubit Clifford test finds no CSS image. No board entry of either type has
(n, k) = (424, 106), so this cannot be a block-Clifford relabeling of a board entry. The fingerprint and WL signature match
nothing on the board. We did not test general multi-qubit Clifford equivalence to codes off the board.

## Dead ends

Most of the 1,690 split patterns hit lift-independent caps of 12, 16 or 18. Random labels, GF(4)-linear labels, odd row
counts, two-block sigma-paired and non-mirror oriented constructions all stayed at d <= 12. The design that reached 22 is
described with the [[488,123,22]] and [[568,143,22]] submissions.

## Tools

Found with the Hyra 2.0 research agent. Our own GPU Pauli-weight information-set search ran on NVIDIA H20 GPUs. The
repository's submission kit, verifier, `verify/ris_gpu.py` and gf2_fast accelerator were used unchanged.
