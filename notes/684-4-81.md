# [[684,4,81]] — weight-8 generalized bicycle on the affine group Aff(F_19)

## Direction & hypothesis

Issue #4162 asks for codes in the box `n <= 1000, w <= 8`, and the
weight-8 × unrestricted cell was thin at large `n`. The families that populate
the efficiency frontier sit at check weight 12 to 32, so `w = 8` near
`n ~ 700` had little in it. The structural bet: generalized bicycle over a
non-abelian group rather than a cyclic one. `Aff(F_q)` (the structure behind
Kasai's affine-coset construction) has order `q(q-1)`, so a 2BGA block lands at
`n = 2q(q-1)` — `q = 19` gives `n = 684` exactly — and two weight-4 supports
give check weight 8 with no tuning.

## What was searched

- **First probe, dropped immediately:** cyclic generalized bicycle
  (`research/kit/search.py`, `sample_cyclic_gb`), 3 sampled at seed 1. It
  reached high rate (`[[646,182,<=84]]`, `[[650,146,<=94]]`) but at check
  weight 32, outside the `w <= 8` box. Right rate, wrong cell.
- **Main sweep:** `research/kit/search.py`, `sample_kasai_affine`, `weight=4`,
  `q_range=(7,19)`, `num=20`, `seed=2`. Screened with `search.screen` at 500
  NumPy RIS trials, `min_k=4`, `min_d=4`, `board="flag"` (direct-sum reject,
  fingerprint dedup, Weisfeiler-Leman flag). 15 of 20 survived.
- **Packaging:** top 7 built through `submit.make_submission` / `save_submission`
  with witnesses from `verify/gf2_fast.cpp`'s `dem_rand_witness`, 200,000
  trials per side per seed, seeds 0 and 1, `pair_depth=24`, 8 threads.
- **Confirmation:** independent `distance_rand` passes on the fast backend at
  100k, 1M, 2M, 4M, then 8M trials per side (8M being the depth CI's own
  gate reaches), run separately from the packaging search.
- All 7 went through `research/kit/coordination.py gate`
  (`verify/validate_candidate.py` unchanged): 7 of 7 `passed: true`, one of them
  board-advancing.
- Campaign record: `research/campaigns/affine-2bga-n684/campaign.json`.

## Dead ends

- Cyclic GB reaches the high-rate cells the issue wants but only at check weight
  24–32. Nothing in that family fits `w <= 8` at the sampled depths.
- **The issue's Option A target (`k/n >= 0.15`) was not reached.** The affine
  family at `w = 8` produces `k = 4..10` over `n = 220..684`, i.e. rate 0.006 to
  0.045, so it competes on `d`, not on rate. The high-`k` cells the bicycle
  families cannot reach are still open.
- `[[684,8,6]]` was flagged `board_wl` (WL signature matches
  `codes/684-8-54.json`) and dropped as a probable permutation.
- 6 of 7 packaged candidates were dominated; only the `d` axis opened.

  at ~10–15 minutes per `n = 684` code. The 20-candidate screen itself was
  seconds.

## Reproduction

Rebuild from parameters using only committed code:

```python
import sys; sys.path[:0] = ["research/kit", "verify"]
from group_algebra import metacyclic, build_2bga

# Aff(F_19) = Z_19 x| Z_18 with 2 a primitive root mod 19; order 342.
# Elements (i, j) sit at index i*18 + j.
mul, _ = metacyclic(19, 18, 2)
HX, HZ = build_2bga(mul, a=[167, 268, 58, 61], b=[284, 292, 32, 6])
# HX = [L(a) | R(b)], HZ = [R(b)^T | L(a)^T], each 342 x 684.
# check weight = |a| + |b| = 8;  css_fingerprint = 7de25c54625485fc
```

The entry itself carries `H_X`, `H_Z` and both witnesses, so
`uv run python verify/qldpc_verify.py codes/684-4-81.json` re-checks the whole
claim without rebuilding anything.
