# [[684,6,77]] — affine 2BGA code on Z_19 x| Z_18, check weight 8, a frontier extension

## Direction & hypothesis

Cell: CSS, `weight-8`, `unrestricted`. n = 684 is under the 700 cap, so the
`w <= 8` and `d <= 40` conditions attached to the `n <= 1000` extended tier do
not apply (schema/SCHEMA.md), even though this entry's check weight is 8.

This cell is the crowded one: 398 entries, 369 at n <= 700, and **176 of them
on the frontier**, led on efficiency by [[682,32,42]] at kd^2/n = 82.77. This
entry scores kd^2/n = 52.009 and beats no existing entry; it is a frontier
extension, which the board counts because ranking is Pareto over (n, k, d, w)
rather than by the efficiency leader. The hypothesis was that the sampler which
produced [[684,4,104]] (check weight 12, `weight-9plus`, where it beat nothing)
would land somewhere open at monomial weight 4.

Rather than guess the bar, research/does_it_advance.py measured it: at n = 684
**every reachable k needs d >= 57**, because [[672,14,56]] dominates anything
at d <= 56 regardless of k; at n = 544, k = 4..12 need d >= 42 and k = 2 needs
48. The boundary is measured, not inferred — `[[684,4,57]]` reports advancing
and `[[684,4,40]]` reports dominated on the same filter the gate uses. At 77
this entry clears that bar by 20.

The k that reach those bars are common: over 300 draws, k=2 53, k=4 47, k=6 30
at n=684 (k=4 49, k=6 32 at n=544). The one route to a looser bar, k >= 33,
occurred 0 times — so it was never a plan.

## What was searched

`sample_kasai_affine(4000, q_range=(17,19), weight=4, seed=11)` with
`--only-k 2,4,6`, screen at 50 RIS trials: 3977 survived k>=2, d>=4, of which
3198 kept. Top 20 by efficiency refined at 20000 trials; all 20 are committed
with their monomial lists in research/kasai_sweep_refined.json.

The `--only-k` filter is load-bearing. Efficiency ranks **high** k first while
the distance needed to advance is roughly k-independent, so a refine budget
ranked on `k*d^2/n` spends itself on the k that cannot reach the bar — which is
how [[684,14,96]] was produced in the first place.

## Evidence trail

Every number is a witness-backed **upper bound**, never a certificate:

**The coarse reading overstated by 44.** 121 became 77. Efficiency goes as d^2,
so the error is squared, and only the refine pass plus deep re-measurement catch
it.

**A local plateau is not a floor.** 91 held at both 100000 and 400000 trials,
which is what convergence looks like — and it was wrong by 14.

**Local gate depth is not CI depth.** `verify/gate_changed.py` budgets
`min(8_000_000, 150*trials)` for a frontier-advancing claim against
`validate_candidate`'s 8000 — about 1000x. Ten independent local passes all
reported "no lighter logical", and every one was consistent with a claim 14 too
high. [[684,4,104]] went the same way: filed at 111, a 12M-trial re-search took
it to 105, and an 8M-trial CI refutation found a weight-104 Z logical.

**77 is the lightest witness across roughly 80M trials, not a certified
distance.** Eight searches returned 85, 83, 83, 87, 80, 82, 87, 77. The record
low kept falling — 83, then 80, then 77 — and the minima arrive at the deadline
rather than settling (CI's 80 came at 7.91M of 8M). What the runs jointly
establish is a bound.

**The instrument is not neutral.** The gate searches at `pair_depth=8`
(verify/gate_changed.py), while board entries have been re-measured at 16, 24,
32, 48 and 64 — the repo's own note on a sibling entry warns that reading a
claim made at 24-80 "at the default of 10 reads high for a reason that is the
instrument, not the code". The true distance may be below 77 for that reason
alone.

## Dead ends

- **d was refuted four times: 91, 85, 83, 80.** Each refutation printed a
  witness (85 Z, 83 X, 80 Z, 77 X) and each is embedded here; the filed value
  is the lightest. `witness_provenance` records each side against the run that
  produced that witness, at 8000000 trials.
- **The displacement claim was lost on the way down.** At d = 80 this entry
  dominated [[698,2,79]] by 1; at 77 it no longer does (that needs 79), so
  `advances_by` is empty and `beaten entries` is 0. It remains board-advancing
  as a frontier extension down to 57. Earlier revisions of this PR said
  "displaces"; that was true then and is not now.
- **The accelerator can be missing without saying so.** A git worktree does
  not carry `verify/*.so`, so an early `gate_changed` run executed with
  `GF is None`, did only the Python seeds, and reported a pass at 3 x 107080
  trials. The tell is the absent `+ fast x N` in its summary line;
  `make fast` in the worktree restored it.
- **d = 102 was never close** — refuted 1 run in 10 by the *shallow* 8000-trial
  gate, which then passed 10/10 on 91.
- **Eleven of the twenty refined finalists collapsed** from ~120 to 18 at
  20000 trials. The majority of the shortlist was inflation.
- **[[684,14,96]] was refuted twice over:** a weight-40 logical under the
  claimed 96, and WL equivalence to the existing entry 684-14-54.json.
  research/does_it_advance.py had called it a 13-entry advance — a pre-filter,
  not a verdict; the gate is authoritative.
- **Matching the staged candidate back to its spec by fingerprint failed.**
  The fingerprint `screen` stamps and the one the verifier computes are
  different values; the spec was recovered by rebuilding each dumped record and
  comparing HX and HZ for equality.
- **`make_submission` searches on the pure-numpy path** and did not finish
  400000 trials in 90 minutes; witnesses were measured elsewhere and passed in,
  where it re-validates them against commutation and row-space membership. It
  stamps `tool = surrogate.lightest_logical` and one shared trial count on both
  sides, so `witness_provenance` is written per side instead.

## Reproduction

```python
import sys, numpy as np
sys.path[:0] = ["research", "research/kit", "verify"]
from search import sample_kasai_affine, screen
from kasai_affine_sweep import rebuild
from css import compute_k
from surrogate import distance_rand_witness

recs = screen(sample_kasai_affine(4000, q_range=(17, 19), weight=4, seed=11),
              min_k=2, min_d=4, trials=50, seed=11, backend="auto", workers=8)
spec = next(r["spec"] for r in recs
            if r["n"] == 684 and r["k"] == 6 and r["spec"]["a"] == [90, 252, 75, 64])
HX, HZ = rebuild(spec)
print(HX.shape, HZ.shape, int(HX.sum(1).max()))   # (342, 684) (342, 684) 8
print(compute_k(HX, HZ))                          # 6
w = distance_rand_witness(HX, HZ, trials=400000, seed=3, backend="auto")
print(w.weight, w.side)                           # 91 Z  <- local plateau only
```

That last line is the trap this note exists to record: it reads 91, and the
claim is 77. The number that constrains the distance is the one the accelerated
refutation returns at 8M trials, not the one a bounded probe settles on.

The arrays are committed verbatim in codes/684-6-77.json under `checks.X` /
`checks.Z`, so the code rebuilds without rerunning the search, and
`qldpc reproduce 684-6-77` reads that file.
