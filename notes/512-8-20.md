# [[512,8,20]] — single-layer weight-8 tile code, radius exactly 4.0

## Direction & hypothesis

Targeted the `weight-8 × local-2d-single` track cell, which was the thinnest on
the board: its headline `kd^2/n` was 8.33, held by the small `[[60,20,5]]` in
`codes/60-20-5.json`, against published 2D-local bars of 8.3 (`[[282,12,14]]`)
and 12.7 (`[[512,18,19]]`).

The opening was a single number. The whole k = 18 B=4 weight-8 tile family sits
at interaction radius sqrt(18) = 4.2426 — 6% over the 4.0 single-layer cap — and
is therefore confined to `local-2d-bilayer`. `fieldnotes/2026-10-10-tile-codes-09171-tile-is-machine-readable.md`
records that the published arXiv:2504.09171 tile is a **4x4** box. So the
hypothesis was: a support pair confined to a **3x3** box would clear the cap,
and the question was whether it still encodes anything.

## What was searched

Support-pair sweep over disjoint 4 + 4 subsets of a 3x3 monomial box — 630
pairs — each built with `research/local2d/boundary_engine.py`
`build_planar(8, 8, S_f, S_g)`, secondary boundary stabilizers of weight > 8
dropped (they lie in the row space of the weight-8 rows, so rank is unchanged),
then CSS-commutation checked and `k` computed.

Of the 630 pairs built, 198 produced the full n = 2·8² = 128 lattice with
commuting checks; the rest lost qubits to the builder's boundary cleanup. The
distribution over those 198:

| k | 2 | 6 | 7 | 8 |
|---|---|---|---|---|
| pairs | 8 | 12 | 20 | **158** |

**k = 8 is the ceiling for this shape** — no 3x3-box weight-8 pair reached k = 10.

Radius was then measured on the checks under the board's own single-layer
pattern (below), and **6 of the 158** landed at radius <= 4.0. Distance was
screened with `research/kit/surrogate.py` `distance_rand`, gf2_fast backend,
8 threads, `pair_depth=12`, 80,000 trials per run:

| pair (S_f, S_g) | radius | d at L=8 / 12 / 16 | kd^2/n at L=16 |
|---|---|---|---|
| A `((0,0),(1,2),(2,1),(2,2))`, `((0,1),(0,2),(1,0),(2,0))` | 4.0000 | 8 / 12 / 16 | 4.00 |
| **B `((0,0),(1,2),(2,1),(2,2))`, `((0,2),(1,0),(1,1),(2,0))`** | **4.0000** | **8 / 15 / 20** | **6.25** |
| C `((0,1),(0,2),(1,0),(2,2))`, `((0,0),(1,1),(1,2),(2,1))` | 3.6056 | 2 / 2 / 2 | 0.06 |
| D `((0,1),(1,0),(1,1),(2,2))`, `((0,0),(0,2),(1,2),(2,1))` | 3.6056 | 2 / 2 / 2 | 0.06 |
| E `((0,2),(1,1),(2,0),(2,1))`, `((0,0),(0,1),(1,0),(2,2))` | 4.0000 | 8 / 15 / 20 | 6.25 |
| F `((0,2),(1,2),(2,0),(2,1))`, `((0,0),(0,1),(1,0),(2,2))` | 4.0000 | 8 / 12 / 16 | 4.00 |

C and D have the *best* radius and the worst codes: they screen to d = 2 at
every size. Pair B was submitted.

## Evidence trail

All claims are witness-backed **upper bounds**, never exact.

- **Deep screen**: `distance_rand`, gf2_fast, 8 threads, `pair_depth=16`,
  **2,000,000 trials**, seed 0, 280 s — lightest logical found **20**.
- **Packaged witnesses**: X side weight 23 (NumPy `lightest_logical`, 1500
  trials, `pair_depth=8`); Z side weight **20** (gf2_fast, 60,000 trials,
  `pair_depth=14`). `d = min(23, 20) = 20`.
- **Gate**: `uv run --extra research python research/kit/coordination.py gate <path>`,
  seed 1335003665, exit 0, `passed: true` —
  `verify` ok with `locality_class=local-2d-single`, `weight_class=weight-8`;
  `dedup` no exact duplicate and no WL-equivalent entry; `refute` no lighter
  logical in 8000 RIS trials; `novelty` `board_advancing=true`,
  `dominated_by=[]`.
- **Cell context**: it advances by sitting on the frontier rather than by taking
  the headline — `kd^2/n` 6.25 against the cell's 8.33. No board entry at
  n <= 512 carries k >= 8 and d >= 20 in this cell.

## Dead ends

- **Layout annealing** (the `tri_hinge_anneal.py` family of move set, hinge cost
  at target 3.98, cap 1, hex lattice): six independent chains of 1e7 iterations
  from a random start converged to **radius 6.56-7.21**, not 4.0. A seeded run
  from the best structured start reached 7.81 after 3e6 iterations. The layout
  search does not close a 40% gap; the support search does, for free.
- **Rigid block offsets**: the best rigid integer offset measures **5.099 — and
  that number was wrong**. It is a 2-qubits-per-site layout: both blocks are full
  L x L grids, so any relative shift smaller than L stacks them, and the spacing
  check counted *distinct* sites, which stay exactly 1 apart while occupancy is
  2. The cap-2 bilayer grid scores best of all under a radius-only objective. Any
  occupancy check here must read qubit coordinates, not `np.unique`.
- **Off-target pairs**: the two best-radius pairs (3.6056) are trivial at d = 2.
  A smaller radius buys nothing if the code is not there.

## Reproduction

Exact parameters; both supports are 4-subsets of a 3x3 box.

```python
import sys, numpy as np
sys.path[:0] = ["research/kit", "research/local2d", "verify"]
from boundary_engine import build_planar
from css import verify_css, compute_k

SF = ((0, 0), (1, 2), (2, 1), (2, 2))
SG = ((0, 2), (1, 0), (1, 1), (2, 0))
HX, HZ, _ = build_planar(16, 16, SF, SG)          # n = 2*16*16 = 512, k = 8
HX = np.asarray([r for r in HX if r.sum() <= 8])  # drop weight>8 boundary rows
HZ = np.asarray([r for r in HZ if r.sum() <= 8])
assert verify_css(HX, HZ) and compute_k(HX, HZ) == 8

# layout: unit square lattice rotated 45 degrees, blocks on the two sublattices
n = HX.shape[1]; L, M = 16, 16 * 16
idx = np.arange(n)
blk, gi, gj = idx // M, (idx % M) // L, idx % L
coords = np.stack([gi + gj + blk, gj - gi], 1).astype(float)   # injective; spacing 1
```

The layout pattern is the one already used by `codes/572-8-19.json`. Under it a
same-block pair separated by `(di, dj)` sits at Euclidean distance
`sqrt(2*(di^2 + dj^2))`, so radius <= 4.0 holds exactly when every check spans
`di^2 + dj^2 <= 8` — a 3x3 box. The published 4x4 tile reaches `(3,3)` and lands
at 4.2426, which is the whole reason it cannot enter this cell.
