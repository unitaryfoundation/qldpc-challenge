# [[84,38,3]] — self-dual PSL(2,7) {7,7} hyperbolic surface code

Three codes from one paper, filed together: [[84,38,3]], [[330,68,6]] and
[[546,236,4]]. This note covers the first; the other two are in
`notes/330-68-6.md` and `notes/546-236-4.md`. All three are rebuilt from the
algebraic construction of arXiv:2610.10948 by `research/hyperbolic_psl.py`.

## Direction & hypothesis

Target cell: **weight-8 / unrestricted**, family `topological`.

The hypothesis was arithmetic rather than algorithmic. A closed-surface
hyperbolic code has `k/n = (p-4)/p + 2/n` by Euler, so the {7,7} tiling pins
the rate near 3/7 ≈ 0.43 at every admissible blocklength, with check weight 7.
The board's weight-8/unrestricted cell is deep at large n (the frontier runs to
`kd²/n` ≈ 123) but everything in it sits at `k ≤ 230` with `n ≥ 700`. Nothing
occupied *small n at high k*, which is exactly the corner a rate-0.43
constant-weight code fills.

## What was searched

The search is over **generator classes**, not over code families, because the
construction is algebraic. For each `(p, q)`:

- `Q = Δ_p / Γ` with `Q ≅ PSL(2,q)` for prime `q`;
- a projective involution `J ∈ PGL(2,q)` (split or non-split) imposes
  `y = JxJ⁻¹`, embedding the face–vertex swap;
- admissible pairs satisfy `ord(x) = ord(y) = p` and `ord(xy) = 2`, and generate
  all of `Q`;
- cells are `edges = ⟨xy⟩`-cosets (data), `faces = ⟨x⟩`-cosets (Z checks),
  `vertices = ⟨y⟩`-cosets (X checks).

Classes are deduplicated on the signature of the check supports. For `p=7,
q=7` this yields **84 distinct classes**, every one giving `n = 84`, `k = 38`;
all 84 measured `d = 3` on both sides. That matches the paper's Table 2 entry
`[[84,38,3]]` exactly.

Also swept `p=5, q=5` (30 distinct classes, all `[[30,8,3]]`) — **dropped**,
already on the board as `codes/30-8-3.json`; re-filing it would be a duplicate.

Screening: every class measured with `research/kit/surrogate.lightest_logical`
on a fresh seed, witnesses confirmed by `validate_logical`.

## Evidence trail

Confirmation ladder for the submitted code (trials/side → lightest logical
found), X and Z independently:

| trials/side | d_X | d_Z |
|---|---|---|
| 2,000 | 3 | 3 |
| 20,000 | 3 | 3 |

The ladder is **flat**: both depths settle at weight 3 on both sides, and no
lighter operator surfaced at either. The claim is therefore a witness-backed
upper bound `d ≤ 3`, **not** certified exact. The witnesses carried in
`codes/84-38-3.json` are X = `[7, 29, 40]` and Z = `[41, 48, 74]`.

`./qldpc submit` re-searched independently through its 2,000,000-trial
accelerator pass and did not tighten either side, which is the strongest
refutation evidence available at this size. That pass returned its own witnesses
rather than the ones found during the sweep; the committed file carries the
submit pass's operators.

Gate verdict: `passed: true`, `board_advancing: true`, `dominated_by: []`,
`advances_by: [d, k, n]`.

## Dead ends

- **The paper's headline codes are unfileable.** [[51330,17112,10]],
  [[51330,10268,12]], [[17220,7382,8]], [[25944,12974,8]] and [[7440,1490,10]]
  sit 1.7×–51× over the board's blocklength cap (`n ≤ 700`, extended to 1000
  only for `w ≤ 8` and `d ≤ 40`). No confidence tier changes that. This is the
  whole reason the admissible slice of the paper is three small codes rather
  than the `kd²/n ≈ 33` result the paper is built around.
- **The paper's modular half is not board material.** Sections IV–VI — module
  partitions, the `R`/`K` routing metrics, Stim/PyMatching threshold estimates —
  are explicitly out of scope under `TRACKS.md`; a module assignment earns at
  most the Layer-3 `modular` flag, which is not ranked. Roughly 60% of the
  paper contributes nothing here.
- **Enumerate-then-measure in one pass does not scale.** Measuring all 660
  classes at `q=11` blew the time budget for no gain, since every class shares
  `n`, `k` and `w` and only `d` varies. Deduplicating first and measuring one
  representative per size is what made the sweep tractable.

## Tools

Model: `human` (claimed, not verified). Harness: opencode. Construction script:
`research/hyperbolic_psl.py`. Repo tooling: `research/kit/css.compute_k`,
`research/kit/surrogate.lightest_logical`, `research/kit/submit.make_submission`
/ `save_submission`, and `verify/validate_candidate.py` via
`research/kit/coordination.py gate`. Compute: roughly 114 candidate codes
constructed and screened, the bulk of it the class enumeration, which
re-derives the order-`|Q|` closure per candidate pair and dominates runtime
before any distance search starts.

## Reproduction

```bash
uv run --extra research python research/hyperbolic_psl.py 7 7 --list
uv run --extra research python research/hyperbolic_psl.py 7 7 --build 0 --outdir out
```

`--build 0` writes `Hx.npy` / `Hz.npy` for the submitted code; verified to
regenerate the submitted `H_X` / `H_Z` row for row.

The matrices are **recomputed from the published construction, not copied**.
arXiv:2610.10948's data-availability statement offers its parity-check matrices
"from the corresponding authors upon reasonable request", so no machine-readable
artifact was available to copy and none is cited as evidence here.

On novelty: the closest prior art on the board is five *planar* hyperbolic codes
mined from a pinned catalogue (`notes/660-68-8.md`,
github.com/QEC-pages/Quantum_LDPC_Codes @ `1c95489383564e4dc2cce517de00d64d6f2c4f56`,
`Hyperbolic_Codes_Planar.zip`). Those are a different construction — planar with
boundary, not closed `PSL(2,q)` quotients — so this is not a reproduction of
them, but they are the codes a reader should compare against. The gate labels
`literature_novelty` UNVERIFIED for every candidate; it does not check the
literature, so that label carries no information either way.
