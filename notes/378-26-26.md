# [[378,26,26]] — weight-8 bivariate bicycle code on Z_21 x Z_9

## Direction & hypothesis

Cell `weight-8 x unrestricted`, CSS board, n between 330 and 400. Before
this campaign the weight-8 frontier there ran 336-88-12, 336-28-20,
336-24-24, 372-14-29, 376-98-8, 378-32-19, 378-18-27 and 392-102-14: no
weight-8 entry with n <= 392 and k >= 26 had d above 20, and the best
k >= 24 point was 336-24-24. The hypothesis was that four-plus-four-term
bivariate bicycle (BB) codes on tori with 2lm in 300..400, drawn at random
and prefiltered for k >= 16, could reach the k >= 26, d >= 24 region.
[[378,26,26]] does: no board entry has n <= 378, k >= 26, d >= 26 and check
weight <= 8, and both margins hold ([[378,24,26]] and [[378,26,24]] are not
dominated either). kd^2/n is about 46.5, against 41.1 for 336-24-24.

## What was searched

Random-support BB codes H_X = [A | B], H_Z = [B^T | A^T] with A and B four
monomials each, both containing 1 (no loss of generality), on every torus
Z_l x Z_m with l >= m >= 3 and 300 <= 2lm <= 400, the torus drawn uniformly
from that list and the other three monomials of each polynomial uniformly
from the torus.

Random supports rarely give k >= 16, so the sweep ran a parallel
generate-and-rank prefilter: 300,000 draws (seed 92), of which 1,338 had
k >= 16 and a connected Tanner graph (research/kit/prescreen.block_structure).
Those went through research/kit/search.screen with the gf2_fast backend at
400 trials; 33 advanced the board frontier at screen depth and were
confirmed at 20,000 / 200,000 / 2,000,000 fast trials
(research/kit/surrogate.distance_rand_witness, pair depth 8), dropping a
candidate as soon as its running bound stopped advancing and skipping any
already dominated by a point staged earlier in the campaign. Three were
staged: this code, a [[360,18,27]] on Z_60 x Z_3 and a [[378,18,29]] on
Z_63 x Z_3.

## Evidence trail

Witness-backed **upper bound** d <= 26, not an exact distance.

| stage | trials per candidate | lightest logical |
|---|---|---|
| screen (gf2_fast, seed from fingerprint) | 400 | 34 |
| confirm | 20,000 | 27 |
| confirm | 200,000 | 26 |
| confirm | 2,000,000 | 26 |
| deep ladder, 3 fresh seeds (54530, 62449, 70368), gf2_fast | 10,000,000 each | 26, 26, 26 |

The bound reached 26 at 200,000 trials and then held; it is still only an
upper bound.

`verify/validate_candidate.py` (through research/kit/coordination.py's gate
wrapper) returned `passed: true`, `board_advancing: true`, `d_only_gain:
false`, label "advances the weight-8 x unrestricted board". Literature
novelty is unverified; board-relative novelty comes from
verify/validate_candidate.py (fingerprint and Weisfeiler-Leman dedup
against every board entry found nothing).

## Dead ends

- Earlier prefiltered 4 + 4 BB sweeps over the whole 222..400 band
  (100,000, 200,000 and 300,000 draws) peaked at k = 18..20 above n = 340
  ([[384,16,30]], [[392,18,28]], [[392,20,26]]); restricting the torus
  list to 2lm >= 300 roughly doubled the share of n >= 300 draws and found
  this k = 26 point.
- A 3 + 5 split of the same check weight (300,000 and 400,000 draws) gave
  only k = 16 points ([[360,16,28]], [[294,16,24]]).
- Cyclic generalized-bicycle codes with a designed divisor g | x^m - 1,
  weight-4 a and b (check weight 8): weight-4 multiples of g exist only for
  deg g <= ~22 at odd m from 111 to 200, and 4,000 such draws at
  300 <= n <= 400 gave nothing advancing even at 400 trials.
- Random-support 2BGA on non-abelian groups at check weight 8, 16,000
  serial plus 150,000 prefiltered draws: every screen-depth survivor
  collapsed by 20,000 trials.

## Reproduction

Torus Z_21 x Z_9 (x of order 21, y of order 9), terms (i, j) = x^i y^j:

A = 1 + x^2 + x^3 y^2 + x^8 y^5,
B = 1 + x^10 y^8 + x^18 y^8 + x^20 y.

```python
import sys; sys.path[:0] = ["research/kit", "verify"]
from bb import build_bb
from css import compute_k
HX, HZ = build_bb(21, 9, [(0, 0), (2, 0), (3, 2), (8, 5)],
                  [(0, 0), (10, 8), (18, 8), (20, 1)])   # n = 378
assert compute_k(HX, HZ) == 26
```

Check sets match codes/378-26-26.json row for row in this order. Witness
search: `surrogate.distance_rand_witness(HX, HZ, trials=2_000_000,
seed=94000276, backend="fast", pair_depth=8)` returns a weight-26 logical.
