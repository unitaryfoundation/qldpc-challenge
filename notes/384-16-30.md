# [[384,16,30]] — weight-8 bivariate bicycle code on Z_24 x Z_8

## Direction & hypothesis

Cell `weight-8 x unrestricted`, CSS board, n between 360 and 400. Before
this filing the weight-8 frontier there ran 360-10-28, 364-8-32,
368-2-35, 372-14-29, 378-32-19, 378-18-27, 390-10-32 and 392-8-33: at
n <= 384 every weight-8 entry with d >= 30 had k <= 8, and every entry with
k >= 16 had d <= 27. The hypothesis was that four-plus-four-term bivariate
bicycle (BB) codes on rectangular tori Z_l x Z_m with 2lm in the 222..400
band could put a k = 16, d = 30 point there. [[384,16,30]] does: no board
entry has n <= 384, k >= 16, d >= 30 and check weight <= 8, and both margins
hold ([[384,14,30]] and [[384,16,28]] are not dominated either).

## What was searched

Random-support BB codes H_X = [A | B], H_Z = [B^T | A^T] with A and B four
monomials each, both containing 1 (no loss of generality), on every torus
Z_l x Z_m with l >= m >= 3 and 222 <= 2lm <= 400, the torus drawn uniformly
from that list and the other three monomials of each polynomial uniformly
from the torus.

Random supports rarely give k >= 16, so the sweep ran a parallel
generate-and-rank prefilter: 200,000 draws (seed 72), of which 927 had
k >= 16 and a connected Tanner graph (research/kit/prescreen.block_structure).
Those went through research/kit/search.screen with the gf2_fast backend at
400 trials; 16 advanced the board frontier at screen depth and were
confirmed at 20,000 / 200,000 / 2,000,000 fast trials
(research/kit/surrogate.distance_rand_witness, pair depth 8), dropping a
candidate as soon as its running bound stopped advancing. Screen-depth
bounds at this weight are badly optimistic (this code screened at 47); 13 of
the 16 fell below the 336-24-24 / 378-18-27 staircase during confirmation.
The survivors were this code, a [[392,18,28]] on Z_28 x Z_7 (filed
separately) and a [[384,16,28]] that this code dominates.

## Evidence trail

Witness-backed **upper bound** d <= 30, not an exact distance. Because the
claim is d >= 30 the ladder used 20,000,000 trials per seed.

| stage | trials per candidate | lightest logical |
|---|---|---|
| screen (gf2_fast, seed from fingerprint) | 400 | 47 |
| confirm | 20,000 | 32 |
| confirm | 200,000 | 30 |
| confirm | 2,000,000 | 30 |
| deep ladder, 3 fresh seeds (50813, 58732, 66651), gf2_fast | 20,000,000 each | 30, 30, 30 |

The bound reached 30 at 200,000 trials and then held through 2,000,000 plus
60,000,000 fresh-seed trials; it is still only an upper bound.

`verify/validate_candidate.py` (through research/kit/coordination.py's gate
wrapper) returned `passed: true`, `board_advancing: true`, `d_only_gain:
false`, label "advances the weight-8 x unrestricted board". Literature
novelty is unverified; board-relative novelty comes from
verify/validate_candidate.py (fingerprint and Weisfeiler-Leman dedup
against every board entry found nothing).

## Dead ends

- A first prefiltered BB weight-8 sweep (100,000 draws, seed 55, 449 with
  k >= 16) staged only [[320,16,24]] and [[240,20,18]] (filed separately);
  its n >= 360 screen survivors (bounds 32 to 40) fell to 20 to 24.
- Cyclic generalized-bicycle codes with a designed divisor g | x^m - 1,
  weight-4 a and b (check weight 8): weight-4 multiples of g exist only for
  deg g <= ~22 at odd m from 111 to 200, and 4,000 such draws at
  300 <= n <= 400 gave nothing advancing even at 400 trials.
- Random-support 2BGA on non-abelian groups at check weight 8, 16,000
  serial plus 150,000 prefiltered draws (2,881 with k >= 18): every
  screen-depth survivor collapsed by 20,000 trials (dominated by 248-24-18,
  252-26-18, 292-22-23, 336-24-24, 378-18-27).
- Non-abelian lifted products with 1 x 2 bases and weight-(3,2) entries
  (check weight 8): 5,000 draws, nothing advancing.

## Reproduction

Torus Z_24 x Z_8 (x of order 24, y of order 8), terms (i, j) = x^i y^j:

A = 1 + x y^4 + x^7 y^3 + x^16 y^3,
B = 1 + x^13 y^7 + x^15 y + x^19 y^2.

```python
import sys; sys.path[:0] = ["research/kit", "verify"]
from bb import build_bb
from css import compute_k
HX, HZ = build_bb(24, 8, [(0, 0), (1, 4), (7, 3), (16, 3)],
                  [(0, 0), (13, 7), (15, 1), (19, 2)])   # n = 384
assert compute_k(HX, HZ) == 16
```

Check sets match codes/384-16-30.json row for row in this order. Witness
search: `surrogate.distance_rand_witness(HX, HZ, trials=2_000_000,
seed=74000216, backend="fast", pair_depth=8)` returns a weight-30 logical.
