# [[53,8,5]] priced calculus E-PEEL of codes/54-8-6.json

## Direction & hypothesis

2D-local bilayer weight-6 CSS cell, through the layout inherited from the
parent. The priced construction calculus was applied one move deep to every
CSS entry on the board, and this code is the E-PEEL of codes/54-8-6.json
([[54,8,6]], max check weight 6; a bivariate bicycle code reconstructed from
qecdb record 674f1a2f14b554330a5bae44). Peeling qubit 1 with the one X check
that touches it keeps k = 8 and lowers the witnessed distance bound by one,
from 6 to 5, while dropping one qubit. Max check weight stays 6. The layout is
the parent's with the peeled qubit removed; the verifier re-measured its
radius and layer count.

## What was searched

Every C-DELETE-CHECK, E-PEEL, and E-PUNCTURE move on each of the 2,783 CSS
board entries as of 2026-11-02, 1,684,787 moves in all, with the consumer at
github.com/unitaryfoundation/code-calculus @ 1b9a942. Children with a bare
qubit, a disconnected Tanner graph, a Weisfeiler-Leman signature equal to a
board entry or to an earlier child, or parameters already dominated inside the
parent's cell were dropped before any search, leaving 334,191 distinct
children. Children with n <= 60 and an inherited distance bound of at least 2,
and children with 61 <= n <= 100 and a bound of at least 5, were screened with
research/kit/surrogate.lightest_logical at 2,000 RIS trials per side; the
survivors the kit's novelty pre-check called board-advancing were staged with
research/kit/submit.py and gated with verify/validate_candidate.py, one
representative per distinct (n, k, d, max weight, locality) point. This code
is that representative for [[53,8,5]] at max check weight 6. The thirteen
points audited first went to the board on 2026-11-04 (PRs #4588 to #4600);
this one is from the remainder, re-checked against the board of 2026-11-04
with the gate's structural, deduplication, and novelty stages before the
ladder below was run. The screen distance is a witness-backed upper bound; the
rungs below are the independent confirmation runs on the staged file.

## Reproduction

Load codes/54-8-6.json, delete qubit 1 (0-based index in that file) together
with its unique X check a2, where the X rows are numbered a1, a2, ... in file
order after dropping rows dependent on earlier ones, as
CodeState.from_challenge in machine/priced_calculus.py labels them, and
relabel the surviving qubits in increasing order of their parent indices; in
github.com/unitaryfoundation/code-calculus @ 1b9a942 this is
apply_operation(state, {'op': 'E-PEEL', 'qubit': 1, 'sector': 'X', 'row_id':
'a2'}). Then run research/audits/leader_audit.py ladder on the result with
--ladder 1000000:101,102 10000000:103 to reproduce the confirmation rungs; the
witnesses in the entry are the ones those runs validated.
