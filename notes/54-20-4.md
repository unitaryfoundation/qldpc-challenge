# [[54,20,4]] — topological code sourced from qecdb.org record 67a4adfc

## Direction & hypothesis

Aiming at the weight-6 track's frontier: find
low-check-weight CSS codes that strictly dominate an existing board entry on
(n, k, d). The candidate pool is the qecdb.org database (36,830 records,
mirrored and deduped to 2,369 unique CSS records), which is ~140x denser in
small-block CSS codes than this board.

## What was searched

Full funnel (see fieldnotes/2026-08-15-qecdb-css-funnel.md):

- mirror qecdb.org -> 2,369 unique records (by `_id`) under research/db_dump/
- parse css=True records into (HX, HZ): X rows then Z rows; require CSS
  commutation and k matching the DB (1,013 survived; 133 rejected as GF(4)-
  style Y rows)
- dedupe by stabilizer fingerprint (RREF convention, same as the verifier)
- frontier cross-check per (locality x weight-class) cell against codes/*
- screen with the kit's RIS surrogate (distance_rand, 2k-4k trials x 2 seeds)
- witness extraction + packaging via research/kit/submit.make_submission
  (trials=8000), then the trusted gate verify/validate_candidate.py

## Evidence trail

- Screening d (RIS upper bound, 2-4k trials): held at the claimed value for
  this code's cell.
- The submitted distance is the kit's witness upper bound
  (confidence: upper_bound); the DB's claimed d was never used as evidence.
- Gate: verify/validate_candidate.py -> passed: true; dedup: no exact
  duplicate, no WL-equivalent on the board.

## Dead ends

- 133 CSS records use GF(4)-style Y characters in their rows and were
  excluded (not importable conservatively).
- 2 records ([[85,53,5]], [[89,67,4]]) have check weight 40-44, above the
  schema's per-check cap of 32, and cannot be represented.
- 19 records pass the gate but are dominated on arrival (not board-advancing), so they are recorded here as non-frontier results; 4 more
  share a [[n,k,d]] already occupied on the board and were not submitted.
