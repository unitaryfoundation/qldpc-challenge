# [[957,105,4]] — rotated surface code with a d = 4 lattice of single-plaquette holes, aligned to the boundaries

## Direction & hypothesis

Target: the geometric-efficiency headline, g = 4 k d^2 / (n rho^2 r^4). The
leader was [[925,173,3]] at g = 1.683, a checkerboard (rotated surface code)
on a single layer with nearest-neighbour checks, so r = sqrt(2), rho = 1 and
g = k d^2 / n.

In that family every removed bulk plaquette is one logical qubit. A removed X
plaquette is a weight-4 logical X; the Z strings joining two removed X
plaquettes are logical Z, and their weight is the Chebyshev distance between
the two plaquettes (the X plaquettes form a square lattice rotated by 45
degrees, in which the graph distance is the L1 distance). Same for Z holes.
So a packing of holes at Chebyshev distance >= D in each sublattice gives a
distance-D code with one logical per hole, as long as D <= 4 (a single removed
plaquette is itself a weight-4 logical).

The best packing densities are 1/5 of the plaquettes for D = 3 (the perfect
Lee code) and 1/8 for D = 4 (the lattice (4,0), (0,4) in plaquette
coordinates, one X hole and one Z hole per 4 x 4 block). In the bulk that is

- D = 3: k d^2 / n -> 9/5 = 1.8
- D = 4: k d^2 / n -> 16/8 = 2.0

so D = 4 has the higher ceiling, at the cost of a wider hole-free strip near
the edges. The hypothesis was that the strip cost can be made small by
aligning the period-4 hole lattice to the boundaries.

## What was searched

Boundary alignment. Z strings end only on the Z-type (left, right) edges, and
X strings only on the X-type (top, bottom) edges. So X holes have to keep 3
plaquette columns clear of the left and right edges, and Z holes 3 rows clear
of the top and bottom. Put the X-hole columns and Z-hole rows on residues mod 4
that start exactly at distance 4 from those edges. The forbidden strips then
fall into the gaps the lattice leaves anyway, and only part of one X-hole
column per side is lost.

Scan. Every rectangle W x H <= 1000 qubits with W, H in [24, 41], and every
lattice offset (X column, X row, Z row, Z column offsets in 4 x 4 x 4 x 4
residues). Distance >= 4 was checked exactly for each (see the evidence
trail). Best: 30 x 32, k = 105, n = 960, g = 1.750 (also 28 x 32, n = 896,
k = 98 and 24 x 40, n = 960, both g = 1.750).

Local search. Simulated annealing (8 chains, about 80k moves each) over
plaquette check types {none, X, Z}, including the virtual boundary
plaquettes, and over boundary-site occupancy. Every move kept commutation,
weight >= 2 and exact d >= 4. The best chain trimmed three boundary qubits
from the 30 x 32 patch and moved the two X holes next to them by one
plaquette each, with k unchanged. That gives the submitted [[957,105,4]],
g = 1.7555. The other chains ended between 1.736 and 1.7518.

## Evidence trail

The distance is decided exactly, not sampled. A minimum-weight logical can
always be taken connected in the graph where two qubits are adjacent when they
share a check of the detecting type: each connected component of a
zero-syndrome support has zero syndrome on its own, and if every component
were a stabilizer, so would be the sum. Enumerating all connected supports of
size 1, 2 and 3 on both sides, and testing each zero-syndrome one for
membership in the stabilizer row span, finds no logical of weight <= 3. The
removed plaquettes are explicit weight-4 logicals on both sides. So d = 4
exactly, although the entry, like every board entry, carries it as a
witness-backed upper bound until certified.

| Stage | Result |
|---|---:|
| connected-support enumeration, sizes 1-3, X and Z | no logical, d >= 4 |
| `qldpc submit` witness search (300 python RIS + 200k gf2_fast trials) | d_X <= 4, d_Z <= 4 |
| `verify/validate_candidate.py` | passed, board-advancing, cell weight-4 / local-2d-single |

Layout: integer grid, one layer, minimum spacing 1. Every check is a subset of
one unit square, so the interaction radius is r = sqrt(2) and
g = 4 k d^2 / (n r^4) = 105 * 16 / 957 = 1.7555. Check weights are 2, 3 and 4.

## Dead ends

- Hole lattices not aligned to the edges: a 21 x 21 patch with a
  one-plaquette margin reaches only g = 1.34. Most of the bulk advantage is
  lost in the strips.
- Wrong offset between the Z-hole lattice and the boundary: weight-2 X strings
  run from Z holes in row 1 to the X-type edge. Rejected by the exact check.
- Annealing from the aligned patches gave at most +0.006. The moves are local,
  and swapping a whole boundary segment's type needs several coordinated
  moves through states with d < 4.
- D >= 5 cannot use single-plaquette holes (a removed plaquette is itself a
  weight-4 logical) and needs larger holes; not tried here.

## Tools

Model: Claude Opus 5.5 (Claude Code); human author @vaibhav-baj. Python with
NumPy for construction, the exact low-weight enumeration and the annealing.
GF(2) ranks use Python integers as bit rows. The gf2_fast C++ accelerator
(`verify/gf2_fast.cpp`, built locally with MinGW-w64) ran inside
`qldpc submit`. Compute: about 5 CPU-hours (scan plus 8 annealing chains
of about 40 minutes each) on a 14-core laptop.

## Reproduction

The JSON (`codes/957-105-4.json`) is the full specification: coordinates and
check supports. To rebuild the 960-qubit parent: qubits at (x, y),
0 <= x < 30, 0 <= y < 32. Plaquette (i, j) has corners (i, j), (i+1, j),
(i, j+1), (i+1, j+1) and is X when i + j is even, else Z. Use rotated-surface
weight-2 boundary checks: X on the bottom and top edges next to Z plaquettes,
Z on the left and right edges next to X plaquettes. Remove the X plaquettes at
i in {4, 8, ..., 24}, j in {0, 4, ..., 28}, and the Z plaquettes at
i in {0, 4, ..., 28}, j in {3, 7, ..., 27}. That gives k = 105 and d = 4. The
submitted code trims (4, 30), (4, 31) and (25, 0) from it, moves the X holes
at (4, 28) and (24, 28) to (3, 29) and (25, 29), and adjusts the adjacent
boundary checks; see the JSON.
