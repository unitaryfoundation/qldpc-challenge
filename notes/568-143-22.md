# [[568,143,22]] — split Pauli-labelled circulant code over Z_71, weight 8, Y-free generators

## Direction & hypothesis

Target: the weight-8, unrestricted cell of the stabilizer board, whose best entry by kd^2/n is [[452,115,18]] (82.4),
a symplectic halving (mirror fold) of a CSS pair-partition CPM code. Folds of the strongest
weight-8 circulant CSS parents on the board stayed near that value: in our enumeration, each of their 1,052 admissible
pairings had a logical of weight at most 18. So instead of folding a CSS parent we built non-CSS quasi-cyclic codes
directly from Pauli-labelled circulant permutation blocks. The aim was to keep the distance growth of the (3,8)
pair-partition CPM CSS codes of Okada and Kasai (arXiv:2607.14091) while using non-CSS generators.

## What was searched

A split Pauli-CPM code over Z_P has 6 row blocks and 8 column blocks. Generator (i, s) puts the Pauli Lambda[i][j] in
{X, Z} on qubit j*P + (s + E[i][j]) mod P, for every column block j. Each column block puts X on three row blocks and Z on
the other three, and these 3-sets differ between columns, so the generators are Y-free and every qubit lies in three
X-type and three Z-type generators. Two row blocks commute for every P if the columns where their labels differ can be
matched in pairs with equal exponent differences.

We searched all 1,690 parity-valid label patterns. For each, we solved the pairing equations for the exponents, preferring
pairings with more freedom and rejecting designs that force weight-1 or weight-2 logicals or short cycles inside an
anticommuting 3-row set. The design used here has a one-dimensional line of integer solutions, so each prime lift P gives
one code. Its best witnessed distances by prime were 16, 16, 18, 18, 20, 22, 20, 22, 22, 22, 22 for
P = 41, 43, 47, 53, 59, 61, 67, 71, 83, 97, 113, with k = 2P + 1. This entry is P = 71, the second prime (after P = 61,
[[488,123,22]], submitted as a separate entry) at which we proved the distance. It is not dominated by the P = 61
code because k is higher.

## Evidence trail

Board claim: **d <= 22, witnessed upper bound** (the only confidence the board records for a stabilizer code). The
witness is Y-free and has Pauli weight 22.

Upper-bound searches, none of which found anything lighter than 22:

- GPU Pauli-weight information-set search with correlated steps, 3000 s (6.3e9 steps): returned 22, with 14,302 hits
  at that weight.
- Fresh-elimination GPU search, 2400 s, 4.6e7 eliminations: returned 22.
- GPU search on the Hamming sectors of the symplectic double, 1800 s: lightest Pauli weight among 703 logicals, 22.
- An independent audit with its own seeds: a 3600 s correlated-step run (39,378 hits at 22) and a 2400 s
  fresh-elimination run (745 hits) re-reached 22 and found nothing lighter.
- The repository's `verify/ris_gpu.py` on the 1136-qubit symplectic double, 2,000,000 trials, pair depth 32: best
  weight 22 in both sectors.
- The repository's own gate, run locally as CI runs it (`verify/gate_changed.py` with the base-branch verifier, seed 568143022): orbit-fold passes over 13 detected symmetries, one Python RIS seed of 93,160 trials, and the accelerated pass over 3,310,000 trials before its 90-minute cap (its lightest proposal had weight 22). No logical lighter than 22.

Exactness (not recordable on this board, stated for the reader). We also ran an exhaustive Pauli-weight branch and bound
of the Dumer-Kovalev-Pryadko irreducible-cluster type (the family of Lee et al., arXiv:2609.30069, App. B.2): branching on
anticommuting generators, a disjoint-packing lower bound, and roots taken from the verified Z_71 symmetry. At cap 21 it
exhausted the tree and found no nontrivial logical of weight <= 21. So d = 22. The tree has 2,174,744,435,543 nodes, and
a CPU executor (192 threads, 10,254 s) and a GPU executor (8 GPUs, 1,420 s) built to traverse the same tree reported the
same total. (Unlike the P = 61 code, no separately re-executed coverage certificate was made for this one.) This is our
own unpublished tooling. The repository's certifier minimizes Hamming weight per side, so it
cannot certify a Pauli distance, and the entry stays `upper_bound`.

The CSS double. The generators are Y-free, so the symplectic double (H_X = (A|B), H_Z = (B|A) on 1136 qubits) is a
weight-8 CSS code [[1136,286,22]] with the same rate and kd^2/n as this code (exactly 22, by the Y-free witness and the
exhaustive Pauli lower bound above). It is above the board's length cap. We make no claim of an advantage over CSS codes: the gain is a new
code, and its CSS double matches it.

Equivalence checks. The verifier's single-qubit Clifford test finds no CSS image. No board entry of either type has
(n, k) = (568, 143), so this cannot be a block-Clifford relabeling of a board entry. We did not test general
multi-qubit Clifford equivalence to codes off the board. The fingerprint and WL signature match nothing on the board.

## Dead ends

- Folds of CSS circulant parents: every one of the 1,052 admissible pairings of the ten strongest weight-8 parents had
  a logical of weight <= 18.
- Most of the 1,690 split patterns hit lift-independent caps of 12 to 18. Of about 270 designs without forced harmful
  4-cycles, four reached 20 and only this one reached 22.
- Random labels, GF(4)-linear labels, odd row counts, two-block sigma-paired and non-mirror oriented constructions all
  stayed at d <= 12.

## Tools

Found with the Hyra 2.0 research agent. Our own GPU Pauli-weight information-set search ran on NVIDIA H20 GPUs, and our
own branch-and-bound prover gave the exactness evidence above. The repository's submission kit, verifier,
`verify/ris_gpu.py` and gf2_fast accelerator were used unchanged.
