# [[200,43,19]] halved CPM pair-partition code, (J,L) = (4,10), P = 40

## Direction & hypothesis

Issue #2992 asks for the halved CPM pair-partition codes of arXiv:2609.30069
(Definition 1 with the reversing fold of Proposition 4). The paper's (4,10)
family lists `[[90,21,11]]`, `[[140,31,15]]`, and `[[200,43,20]]` with exact
distances but publishes no generators, and its data repository
(`ultra-high-rate-qec/design-principles-data`) was empty on 2026-10-11. The
construction is fixed up to an exponent array E, so the family can be searched
directly: n = 5P and k = P + 3 for every accepted template, and the distance
is whatever the search finds. Nothing on the board sat near these (n, k) at
these distances, so an instance with a verified bound close to the paper's
value is a board entry even where it falls short of the paper's claim.

## The construction

The parent is a pair-partition CPM code with J = 4 check blocks and L = 10
qubit blocks of size P. X checks come from E: row (j, s) has a 1 at qubit
(l, s - E[j][l] mod P) for each l. Z checks come from D[j][l] = -E[j][l xor 1]
mod P in the same way. E must satisfy the paper's pair-partition rule: each
off-diagonal cell (i < j) carries a perfect matching M on the L block columns,
edge-disjoint from the matchings already placed in its row and column, and
E[i,u] + E[j,u xor 1] = E[i,v] + E[j,v xor 1] mod P for every matched pair
{u, v}. The search draws M at random, solves the resulting homogeneous
integer system for E with sympy, and reduces a random integer combination of
the kernel basis mod P.

The reversing fold identifies qubit t of block l with qubit -t mod P of block
l xor 1. Each parent X check then becomes one stabilizer generator on the 5P
surviving qubits (blocks 0, 2, 4, 6, 8): an X leg on each surviving block's
position and a Z leg on each partner position, with coinciding legs merging to
Y. Every generator has weight at most 10. The 4P generators span a group of
rank 4P - 3, hence k = P + 3.

## What was searched

A Perlmutter run over the (4,10), P = 40 template: 330,958 templates screened
with 800 to 1,000 Pauli-weight RIS trials each; the 120 with the highest screen
readings were re-screened at 300,000 Pauli-RIS trials and the best 15 kept.
Each of the 15 then got 100,000,000 unframed gf2_fast trials on Perlmutter:
only this one held 20, the rest fell to 18 or 19. Under 456 random per-qubit
symplectic frames x 1,000,000 gf2_fast trials (Perlmutter job 59676167, two
replicas, 2026-10-11) a frame found a weight-19 Pauli logical, and nothing
lighter appeared.

## Evidence trail

- Witness: a Pauli logical of weight 19 with X support [20, 31, 73, 74, 77, 88, 120, 154, 159, 165, 175, 186, 193] and Z support
  [6, 20, 70, 73, 77, 103, 120, 123, 154, 189, 192] (positions in both carry Y), stored in the JSON; it commutes with every
  generator and lies outside the stabilizer group, as the gate re-checks.
- Lower bounds: none. The distance is an upper bound from search.
- Accelerator bias: the unframed gf2_fast search on the symplectic doubling
  minimizes |x| + |z|, so a logical with Y legs looks heavier than its Pauli
  weight and can be missed. The frame screen draws a random single-qubit
  symplectic frame per qubit, runs the doubled search, maps each find back,
  and scores it by Pauli weight. On a P = 40 twin of this family, 12 frames x
  500,000 trials found Pauli weight 15 where 100,000,000 unframed trials read
  19, so unframed non-refutations of these codes are weak evidence.
- Gate (`verify/validate_candidate.py` against main bc93ef2d, 2026-10-13):
  passed, no exact or WL duplicate, refuter found nothing lighter,
  `board_advancing` true, `dominated_by: []`, cell `weight-9plus x
  unrestricted` on the stabilizer board.

## Where it sits

No board entry of any type at n <= 200 and k >= 43 reaches d >= 13; the best
is `[[192,43,12]]`. On the stabilizer board the cell `weight-9plus x
unrestricted` had nothing near this (n, k).

The paper's Table VII lists [[200,43,20]] at this lift, as an exact value; the search did not reach 20.

## Dead ends

- The paper's instances cannot be rebuilt from the paper: no arrays appear in
  it or its appendices, and the data repository is empty. Whether the gap to
  the paper's exact value comes from the template search (the paper does not
  say how its E were chosen) or from our distance estimate (an upper bound) is
  open. The V1 result on #2992 records this; the box there is left unticked.
- Plain Pauli-weight RIS in Python at 1,000 to 3,000 trials ranks templates
  only loosely; the ranking that fed the frame screen came from it, so better
  templates may have been screened out early.

## Reproduction

```python
import numpy as np

def halved_checks(P, E):
    J, L = len(E), len(E[0])
    HX = np.zeros((J * P, L * P), dtype=np.int8)
    for j in range(J):
        for l in range(L):
            for s in range(P):
                HX[j * P + s, l * P + (s - E[j][l]) % P] = 1
    checks = []
    for h in HX:
        x, z = [], []
        for ri, l in enumerate(range(0, L, 2)):
            for t in range(P):
                if h[l * P + t]:
                    x.append(ri * P + t)
                if h[(l ^ 1) * P + (-t) % P]:
                    z.append(ri * P + t)
        checks.append({"X": x, "Z": z})
    return checks

E = [[12, 9, 32, 4, 39, 15, 8, 2, 21, 18], [25, 4, 12, 6, 3, 38, 32, 29, 0, 17], [9, 23, 39, 14, 28, 19, 33, 21, 28, 8], [19, 24, 28, 36, 21, 5, 30, 2, 32, 23]]
S = halved_checks(40, E)   # the 4P generators of codes/200-43-19.json, in order
```
