# [[320,16,24]] — weight-8 bivariate bicycle code on Z_40 x Z_4

## Direction & hypothesis

Cell `weight-8 x unrestricted`, CSS board, n between 300 and 340. Before
this filing the weight-8 frontier there held 292-22-23, 294-24-20,
300-12-25, 300-32-15, 306-26-19, 308-10-26, 310-12-26 and 336-24-24: at
n <= 320 no entry with k >= 16 reached d = 24 (the best was 292-22-23), and
every entry with d >= 24 had k <= 12. The hypothesis was that
four-plus-four-term bivariate bicycle (BB) codes on rectangular tori
Z_l x Z_m with 2lm in that range, which the board covers far less densely
than the weight-6 BB family, could put a k = 16, d = 24 point there.
[[320,16,24]] does: no board entry has n <= 320, k >= 16, d >= 24 and check
weight <= 8, and the k - 2 margin holds as well ([[320,14,24]] is not
dominated either).

## What was searched

Random-support BB codes H_X = [A | B], H_Z = [B^T | A^T] with A and B four
monomials each, both containing 1 (no loss of generality), on every torus
Z_l x Z_m with l >= m >= 3 and 222 <= 2lm <= 400, the torus drawn uniformly
from that list and the other three monomials of each polynomial uniformly
from the torus.

Random supports rarely give k >= 16, so the sweep ran a parallel
generate-and-rank prefilter: 100,000 draws (seed 55), of which 449 had
k >= 16 and a connected Tanner graph (research/kit/prescreen.block_structure).
Those went through research/kit/search.screen with the gf2_fast backend at
400 trials; 7 advanced the board frontier at screen depth and were
confirmed at 20,000 / 200,000 / 2,000,000 fast trials
(research/kit/surrogate.distance_rand_witness, pair depth 8), dropping a
candidate as soon as its running bound stopped advancing. Five of the seven
collapsed at 20,000 trials to points dominated by 252-20-21, 292-22-23,
336-24-24 or 378-18-27 (screen-depth bounds of 32 to 40 at n = 360 to 392
fell to 20 to 24). The two survivors were this code and a [[240,20,18]] on
Z_20 x Z_6, which is filed separately.

## Evidence trail

Witness-backed **upper bound** d <= 24, not an exact distance. The screen
saw 26 at 400 trials; the bound fell to 24 at 20,000 trials and has not
moved since.

| stage | trials per candidate | lightest logical |
|---|---|---|
| screen (gf2_fast, seed from fingerprint) | 400 | 26 |
| confirm | 20,000 | 24 |
| confirm | 200,000 | 24 |
| confirm | 2,000,000 | 24 |
| deep ladder, 3 fresh seeds (49437, 57356, 65275), gf2_fast | 10,000,000 each | 24, 24, 24 |

`verify/validate_candidate.py` (through research/kit/coordination.py's gate
wrapper) returned `passed: true`, `board_advancing: true`, `d_only_gain:
false`, label "advances the weight-8 x unrestricted board". Literature
novelty is unverified; board-relative novelty comes from
verify/validate_candidate.py (fingerprint and Weisfeiler-Leman dedup
against every board entry found nothing).

## Dead ends

- Random-support BB at check weight 8 above n = 340: every screen-depth
  survivor with k >= 16 fell below the 336-24-24 / 378-18-27 / 372-14-29
  staircase by 20,000 trials.
- Cyclic generalized-bicycle codes with a designed divisor g | x^m - 1,
  weight-4 a and b (check weight 8): weight-4 multiples of g exist only for
  deg g <= ~22 at odd m from 111 to 200, and 4,000 such draws at
  300 <= n <= 400 gave nothing advancing even at 400 trials.
- Random-support 2BGA on non-abelian groups at check weight 8, 16,000
  serial plus 150,000 prefiltered draws (2,881 with k >= 18): every
  screen-depth survivor collapsed by 20,000 trials (dominated by 248-24-18,
  252-26-18, 292-22-23, 336-24-24, 378-18-27).
- Non-abelian lifted products with 1 x 2 bases and weight-(3,2) entries
  (check weight 8): 5,000 draws, nothing advancing.
- 2BGA coset codes with weight-4 supports on S5, A6, S6, A5 x C_m,
  S4 x C_m: nothing advancing.

## Reproduction

Torus Z_40 x Z_4 (x of order 40, y of order 4), terms (i, j) = x^i y^j:

A = 1 + x^11 y + x^12 y + x^19 y^2,
B = 1 + x^13 + x^23 + x^38 y^3.

```python
import sys; sys.path[:0] = ["research/kit", "verify"]
from bb import build_bb
from css import compute_k
HX, HZ = build_bb(40, 4, [(0, 0), (11, 1), (12, 1), (19, 2)],
                  [(0, 0), (13, 0), (23, 0), (38, 3)])   # n = 320
assert compute_k(HX, HZ) == 16
```

Check sets match codes/320-16-24.json row for row in this order. Witness
search: `surrogate.distance_rand_witness(HX, HZ, trials=2_000_000,
seed=57000165, backend="fast", pair_depth=8)` returns a weight-24 logical.
