# [[972,166,34]] — irregular pair-partition CPM code at the composite lift P = 81, with a rank-deficient cocycle class giving k = 2P + 4

## Direction & hypothesis

Cell: CSS, unrestricted, weight 8, extended tier (n <= 1000 with w <= 8 and
d <= 40). The comparison entry is codes/996-166-32.json, introduced by
@MicheldeMessieres in PR #4045. It uses the pair-partition (PP) method of
Okada and Kasai (arXiv:2607.14091) on an irregular 5 x 12 template at
P = 83, with n = 12P and k = 2P. Its reported distance gives an
upper-bound score kd^2/n = 170.667. The full-row-rank design rate is 1/6;
rank deficiency offers a way to increase k at fixed n.

Hypothesis: a composite lift can increase k at fixed n, with distance
screened separately. Over F_2,
x^81 - 1 has the factor x^2 + x + 1 (Phi_3). If H_X and H_Z both lose rank
on that component, each side's F_2 rank drops by 2 and k rises by 4. Whether
they do depends only on the exponents mod 3, so it can be designed. The
extra logical classes have periodic representatives from the Z_3
quotient, whose weights multiply by 27 when lifted. This does not bound
the weights of all representatives of those classes from below. For
this code, k = 166 and the reported d <= 34 give the upper-bound score
166 * 34^2 / 972 = 197.424.

**Technique (not ours):** the PP commutation rule and CPM lift are Okada and
Kasai's (arXiv:2607.14091); the design-rate count is from Lee, Okada,
Maskara, Kasai and Zhou (arXiv:2609.30069); the 5 x 12 template is the one
introduced by @MicheldeMessieres in codes/996-166-32.json
(notes/996-166-32.md). Ours: the
pairing used here, the integer-lattice exponents, and the rank-deficient
class at a composite lift.

## What was searched

- Pairings: a large-neighbourhood search with exact forced-4-cycle pruning
  around the pairing of codes/996-166-32.json found about 500 4-cycle-free
  pairings of the template. The one used here forces the fewest block
  hexagons found (6 per side; that entry's pairing forces 12), leaves 6 free
  exponent directions, and every block row's link is triangle-free (its
  square complex of rows, columns and one square per pair is nonpositively
  curved).
- Exponents: the integer solution lattice of the paired-difference
  equations, from a column Hermite reduction (27 basis vectors: 21 gauge
  and 6 free), reduced mod 81. Integer solutions satisfy the equations before reduction; a solution
  found only mod a prime need not satisfy them mod 81.
- Rank-deficient classes: coefficient vectors mod 3 were sampled and the
  Z_3 quotient code (n = 36) built for each. A sampled class with k = 10
  instead of 6, from rank loss on Phi_3 on both sides, was fixed and
  the higher digits drawn at random.
- Filter: no block 4-cycle closes (voltage 0 mod 81, nor 0 mod 27, which
  closes after 3 turns), and only the 6 forced block hexagons per side.
- Four filtered draws were screened by full-length Stern with a budget
  of up to 1,000,001 iterations per side. Draws 0 and 3 completed both
  sides. Draws 1 and 2 found weight-14 X logicals after two iterations
  and stopped before the Z screen.
- Matched control at small size, on another 4-cycle-free pairing of the
  same template at P = 39 (n = 468), 10 draws each and 120k iterations per
  side: the deficient class (k = 82) read 18 on five draws and 20 on
  five; an ordinary class (k = 78) read 18 on all ten. This sample showed
  no reduction in the lightest weights found. The draws' hexagon counts
  also differed, so this does not isolate the effect of rank deficiency
  or establish that it preserves true distance.

## Evidence trail

Full-length Stern information-set decoding, both sides, each rung a fresh
seed:

| rung (seeds X / Z) | X iterations | Z iterations | lightest X | lightest Z |
|---|---|---|---|---|
| screen (81102433 / 81102434) | 1,000,001 | 1,000,001 | 34 | 34 |
| round 1 (8111 / 8112) | 3,048,292 | 3,066,137 | 36 | 34 |
| round 2 (8121 / 8122) | 3,079,152 | 3,060,778 | 34 | 34 |
| cumulative | 7,127,445 | 7,126,916 | 34 | 34 |

The round-1 X run found 36; the previously known X upper bound stayed
34. Per-run decoder histograms reported one weight-34 Z support in
round 1, then four X and two Z in round 2. These counts are not
deduplicated across runs. The stored minimum support from each run
was checked; the other histogram entries were retained as counts.

No pure-X or pure-Z logical of weight <= 32 was found in those runs.
Pure-X and pure-Z logicals have even weight: block rows 0, 1 and 2 of
each side sum to the all-ones vector. Restricted searches on block
columns 0-7, the degree-3 columns, reported weight 40 on both sides;
columns 0-5 reported 48. Exploratory quotient searches reported logical
weights 6 for Z_9 (n = 108) and 14 for Z_27 (n = 324), with checked
periodic lifts of weights 54 and 42. These are reported heuristic
upper bounds, not exact quotient distances or exclusions of lighter
folded logicals. Rank H_X = rank H_Z = 403 (two below full),
k = 972 - 806 = 166.

Claim: d_X <= 34 and d_Z <= 34, from stored weight-34 logicals. No lower
bound of 34 is established. For scale, the same search found weight-32
logicals in codes/996-166-32.json within about 0.6M iterations. This
calibration does not exclude a sparse or harder-to-detect layer of
lighter logicals in this code. The trusted gate finds no exact
fingerprint or WL-signature match on the checked board and labels the
point board-advancing. Compared with @MicheldeMessieres's newer public
entry codes/996-166-34.json, this code uses 24 fewer physical qubits
at the same k = 166, reported d = 34 and w = 8. The scores computed
from those distance upper bounds are 197.424 and 192.667.
Literature novelty is unverified.

Near misses: draws 1 and 2 of the same class have weight-14 X logicals on
block columns 0-5 only (the pairs of the template's omitted-edge triangle),
found instantly; a second deficient class read 30 on both of its draws. A
restricted search on columns 0-5 exposes the collapse in seconds and
should be the first filter at a composite lift.

## Dead ends

- Non-abelian two-level lifts of the (3,8) cube design: few non-abelian
  quotients appeared among those tested for the square complex's
  fundamental group. Tested covers gained at most 2 cocycle dimensions.
  At n = 496, 30 twisted and 30 abelian draws read mean 11.6 and 11.5.
- A rate-1/7 6 x 14 template from the Fano plane (rows are complements of 6
  lines, k = 2P + 6): all 32,768 symmetric natural-plus-cross pairings were
  enumerated exactly; the best class (6 free directions, 12 forced
  hexagons per side) read 28 at P = 71.
- 5 x 12 templates whose base matrix has F_2 dependencies (left-out graph
  C4 + K2, k = 2P + 4; three quads, k = 2P + 6): at least 16 and 48 forced
  hexagons per side; at matched n = 492, C4 + K2 read 16 against 22 for the
  pairing used here.
- Rank loss on large cyclotomic factors: none in 300 draws each for the
  5 x 12 designs at P = 73 and 77 or for a 4 x 10 design at P = 73 to 99.
- Z_3 x Z_27 lifts with a class that loses rank on two of the four F_4
  components of the Z_3 x Z_3 quotient (k = 170): the one draw screened
  read 30.
- Sampled random pair-complement pairings had 0 or 1 free exponent
  directions, motivating the structured pairing search.

## Tools

Model: Claude Opus 5.5 (Claude Code), in a stage-only research session for
@jacksongquera. Repo tooling: verify/gf2_fast.cpp (GF(2) ranks),
research/kit/submit.py and research/kit/coordination.py (staging and the
gate), verify/validate_candidate.py, research/does_it_advance.py. The
search is an uncommitted multithreaded Stern decoder (p = 2 per half,
collision window l = 16, 16 random pivot swaps per iteration, logicals
told from stabilizers by their syndromes against the other side's
logicals). This describes the search method; the original uncommitted
implementation is not an executable reproduction artifact. Compute: about
9 CPU-hours for this code's screen and rounds, about 40 for the session,
on a machine shared with another campaign.

## Reproduction

P = 81, n = 972. For block row i (0..4), block column c (0..11) and
r in 0..80, H[i*81 + r, c*81 + ((r + s_ic) mod 81)] = 1 ('-' = empty cell):

```
S_X = [[-,-,-,-,49,3,4,9,11,43,51,51], [-,-,61,49,-,-,53,10,40,22,11,9],
       [49,51,-,-,-,-,26,43,35,57,54,32], [52,65,76,55,40,64,-,-,-,-,39,28],
       [41,77,12,75,67,65,-,-,10,79,-,-]]
S_Z = [[-,-,-,-,1,36,75,80,62,13,0,0], [-,-,31,19,-,-,26,64,35,17,75,73],
       [21,23,-,-,-,-,30,47,37,59,8,67], [48,61,22,1,51,75,-,-,-,-,53,42],
       [13,49,60,42,27,25,-,-,33,21,-,-]]
```

The template and the pairing are written out in this entry's
provenance.construction; for every pair (a, b) of the pairing of X row i
with Z row j, s^X_ia - s^Z_ja - s^X_ib + s^Z_jb = 0 (mod 81).

These arrays reconstruct the submitted matrices exactly. The JSON
stores the full check supports and weight-34 witnesses, which the
trusted verifier checks directly. Reconstructing this code does not
replay the original search, and no kit-constructor recipe is claimed.
