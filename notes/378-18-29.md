# [[378,18,29]] — weight-8 bivariate bicycle code on Z_63 x Z_3

## Direction & hypothesis

Cell `weight-8 x unrestricted`, CSS board, n between 360 and 400. Before
this filing the weight-8 frontier there ran 360-10-28, 364-8-32,
372-14-29, 378-32-19, 378-18-27 (a lifted product over M_27 x Z_7) and
392-8-33. The hypothesis was that four-plus-four-term bivariate bicycle
(BB) codes on long thin tori such as Z_63 x Z_3 could match the k = 18 of
378-18-27 at a larger distance. [[378,18,29]] does: no board entry has
n <= 378, k >= 18, d >= 29 and check weight <= 8, and the k - 2 margin
holds ([[378,16,29]] is not dominated either). Against 378-18-27 (same n,
k and weight) the gain is d-only, which the gate treats as the suspect
axis; it also flagged the two as possibly equivalent (same
Weisfeiler-Leman signature). The matched-depth re-measurement it asks for
is in the evidence trail below: at the same budget the peer reads 27 and
this code reads 29, so the two are not equivalent and the gap is real at
that depth. The deep ladder used 20,000,000 trials per seed because the
claim is d-only.

## What was searched

Random-support BB codes H_X = [A | B], H_Z = [B^T | A^T] with A and B four
monomials each, both containing 1 (no loss of generality), on every torus
Z_l x Z_m with l >= m >= 3 and 300 <= 2lm <= 400, the torus drawn uniformly
from that list and the other three monomials of each polynomial uniformly
from the torus.

Random supports rarely give k >= 16, so the sweep ran a parallel
generate-and-rank prefilter: 300,000 draws (seed 92), of which 1,338 had
k >= 16 and a connected Tanner graph (research/kit/prescreen.block_structure).
Those went through research/kit/search.screen with the gf2_fast backend at
400 trials; 33 advanced the board frontier at screen depth and were
confirmed at 20,000 / 200,000 / 2,000,000 fast trials
(research/kit/surrogate.distance_rand_witness, pair depth 8), dropping a
candidate as soon as its running bound stopped advancing and skipping any
already dominated by a point staged earlier in the campaign. Three were
staged: this code, a [[378,26,26]] on Z_21 x Z_9 and a [[360,18,27]] on
Z_60 x Z_3 (both filed separately).

## Dead ends

- Earlier prefiltered 4 + 4 BB sweeps over the whole 222..400 band
  (100,000, 200,000 and 300,000 draws): the best k = 18 point near
  n = 380 was [[392,18,28]] (filed separately).
- A 3 + 5 split of the same check weight (300,000 and 400,000 draws) gave
  only k = 16 points.
- Cyclic generalized-bicycle codes with a designed divisor g | x^m - 1,
  weight-4 a and b (check weight 8): 4,000 draws at 300 <= n <= 400 gave
  nothing advancing even at 400 trials.
- Random-support 2BGA on non-abelian groups at check weight 8, 16,000
  serial plus 150,000 prefiltered draws: every screen-depth survivor
  collapsed by 20,000 trials.

## Reproduction

Torus Z_63 x Z_3 (x of order 63, y of order 3), terms (i, j) = x^i y^j:

A = 1 + x^8 + x^15 + x^48 y^2,
B = 1 + x^42 y + x^44 y^2 + x^49 y^2.

```python
import sys; sys.path[:0] = ["research/kit", "verify"]
from bb import build_bb
from css import compute_k
HX, HZ = build_bb(63, 3, [(0, 0), (8, 0), (15, 0), (48, 2)],
                  [(0, 0), (42, 1), (44, 2), (49, 2)])   # n = 378
assert compute_k(HX, HZ) == 18
```

Check sets match codes/378-18-29.json row for row in this order. Witness
search: `surrogate.distance_rand_witness(HX, HZ, trials=2_000_000,
seed=94000276, backend="fast", pair_depth=8)` returns a weight-29 logical.
