# [[360,16,28]] — weight-8 bivariate bicycle code on Z_15 x Z_12 with a 3 + 5 term split

## Direction & hypothesis

Cell `weight-8 x unrestricted`, CSS board, n between 330 and 370. Before
this filing the weight-8 frontier there ran 330-10-27, 336-24-24,
336-28-20, 350-8-29, 356-4-31, 360-10-28 and 364-8-32: at n <= 360 no
weight-8 entry with k >= 16 reached d = 25, and the entries with d >= 28
had k <= 10. Bivariate bicycle (BB) codes on the board almost always split
the check weight evenly between the two polynomials (3 + 3 or 4 + 4). The
hypothesis was that an uneven split, |A| = 3 and |B| = 5 (still check
weight 8, and column weight 8), explores a part of the BB space the board
has barely touched and could put a k = 16, d >= 28 point at n = 360.
[[360,16,28]] does: no board entry has n <= 360, k >= 16, d >= 28 and check
weight <= 8, and the k - 2 margin holds ([[360,14,28]] is not dominated
either).

## What was searched

BB codes H_X = [A | B], H_Z = [B^T | A^T] with A three monomials and B five
monomials, both containing 1 (no loss of generality), on every torus
Z_l x Z_m with l >= m >= 3 and 222 <= 2lm <= 400, the torus drawn uniformly
from that list and the other monomials uniformly from the torus.

The split costs rate: only 146 of 300,000 draws (seed 91) had k >= 16 and a
connected Tanner graph (research/kit/prescreen.block_structure), about a
third of the even-split yield. Those went through
research/kit/search.screen with the gf2_fast backend at 400 trials; 6
advanced the board frontier at screen depth and were confirmed at 20,000 /
200,000 / 2,000,000 fast trials (research/kit/surrogate.distance_rand_witness,
pair depth 8), dropping a candidate as soon as its running bound stopped
advancing. This was the only survivor; the others fell to 24 to 26 at
n = 360 to 384, dominated by 336-24-24 and 378-18-27.

## Evidence trail

Witness-backed **upper bound** d <= 28, not an exact distance.

| stage | trials per candidate | lightest logical |
|---|---|---|
| screen (gf2_fast, seed from fingerprint) | 400 | 38 |
| confirm | 20,000 | 28 |
| confirm | 200,000 | 28 |
| confirm | 2,000,000 | 28 |
| deep ladder, 3 fresh seeds (52893, 60812, 68731), gf2_fast | 10,000,000 each | 28, 28, 28 |

The bound reached 28 at 20,000 trials and then held; it is still only an
upper bound.

`verify/validate_candidate.py` (through research/kit/coordination.py's gate
wrapper) returned `passed: true`, `board_advancing: true`, `d_only_gain:
false`, label "advances the weight-8 x unrestricted board". Literature
novelty is unverified; board-relative novelty comes from
verify/validate_candidate.py (fingerprint and Weisfeiler-Leman dedup
against every board entry found nothing).

## Dead ends

- Even-split 4 + 4 BB sweeps in the same band (100,000, 200,000 and
  300,000 prefiltered draws) gave the separately filed [[240,20,18]],
  [[320,16,24]], [[384,16,30]] and [[392,18,28]]; the best 4 + 4 point
  they found at n = 360 was a [[360,16,27]] on Z_60 x Z_3 (screened at
  43), which this code dominates.
- Cyclic generalized-bicycle codes with a designed divisor g | x^m - 1,
  weight-4 a and b (check weight 8): weight-4 multiples of g exist only for
  deg g <= ~22 at odd m from 111 to 200, and 4,000 such draws at
  300 <= n <= 400 gave nothing advancing even at 400 trials.
- Random-support 2BGA on non-abelian groups at check weight 8, 16,000
  serial plus 150,000 prefiltered draws: every screen-depth survivor
  collapsed by 20,000 trials.
- Non-abelian lifted products with 1 x 2 bases and weight-(3,2) entries
  (check weight 8): 5,000 draws, nothing advancing.

## Reproduction

Torus Z_15 x Z_12 (x of order 15, y of order 12), terms (i, j) = x^i y^j:

A = 1 + x^6 y^9 + x^8 y^4,
B = 1 + x y^9 + x^6 y^7 + x^11 + x^14 y^10.

```python
import sys; sys.path[:0] = ["research/kit", "verify"]
from bb import build_bb
from css import compute_k
HX, HZ = build_bb(15, 12, [(0, 0), (6, 9), (8, 4)],
                  [(0, 0), (1, 9), (6, 7), (11, 0), (14, 10)])   # n = 360
assert compute_k(HX, HZ) == 16
```

Check sets match codes/360-16-28.json row for row in this order. Witness
search: `surrogate.distance_rand_witness(HX, HZ, trials=2_000_000,
seed=93000273, backend="fast", pair_depth=8)` returns a weight-28 logical.
